# 04 项目推进与方案审核

## 目的

将资料、人工意见和已有计划转为有依据的工作方案，由相关角色负责人审核，系统在条件满足后应用正式计划并生成后续待办。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| PLAN-001 | 项目管理可请求分析。建议基于固定资料、人工记录和有效计划，来源可查；无需变更时也应说明依据。 |
| PLAN-002 | 方案列明新增、修改或取消的任务，以及各任务的角色、工作内容、输入、成果和完成标准；必要时更新项目背景与目标。 |
| PLAN-003 | 任务依赖须关联上游成果和下游接收标准，区分必需与参考输入，不能只写在任务说明中。 |
| PLAN-004 | 保留未决事项、固定来源和必要确认角色，区分独立准备工作与依赖确认的实施工作；影响须覆盖直接及间接下游。 |
| PLAN-005 | 为全部相关角色生成同一固定方案的审核待办，由负责人查看整体变化、原标准和依据，提交同意或有理由的拒绝；收齐反馈后汇总。 |
| PLAN-006 | 全部相关负责人同意、需求与计划依据仍有效且必要条件满足后，整体应用方案并生成任务；否则保留意见，进入重评或澄清。 |
| PLAN-007 | 可对尚未生效的错误推断提出有据纠正，保留原推断、替代内容、理由和来源，由原、新相关角色负责人随整份方案审核。 |
| PLAN-008 | 方案应公开相关角色的识别结果与理由；项目内角色负责人可针对遗漏角色提出有依据的异议，保存涉及的方案版本、理由和来源。 |
| PLAN-009 | 生效前已受理的遗漏异议应暂缓该方案应用。Agent 核对后，由提异议角色的现任负责人确认回应是否充分；补充角色或修改方案时，形成新版本并重新审核。 |

## 关键规则

- 每个相关角色由一名负责人代表决定；参与者可执行和讨论，无须全体成员投票。一人兼任多个角色时，仍须分别完成各角色审核，项目管理也不例外。
- 初次和后续方案适用同一规则。任一角色拒绝后仍收集其余意见；模型成功、阅读通知、超时和旧方案同意均不能代替本次审核。
- 负责人交接保留已提交的有效决定，未办事项转交继任者；无负责人时不能代为同意，见[项目与角色管理](01-项目与角色管理.md)。
- 遗漏异议只暂缓所指方案，不冻结无关工作。回应仍不充分时继续核对，项目管理不能仲裁为通过；负责人更换仅转交确认责任，不自动解决异议。
- 异议得到充分回应且方案未变化时，保留原有效审核，重新核对生效条件；补角色或改方案须按新版本重新审核。方案已生效后收到的异议进入[问题处理](07-问题澄清与风险处理.md)或[变更流程](06-需求变化与任务整改.md)，不直接撤销已生效结果。
- 必需依赖不得成环或引用不存在、失效的成果。自动检查通过不代表范围和专业判断正确。
- 已知要求保留为标准。独立准备工作可先审核，但完成准备不等于确认未知事项；依赖未知结果的实施工作不能借“准备”名义放行。
- 澄清须由必要角色负责人确认同一固定回答已充分；随后仍须审核实施方案，不自动接收成果或解决问题。
- 推断纠正以本轮实际读取的固定原件、人工记录、有效标准或同问题反馈为依据；不得改写正式约束。未批准方案不能充当正式标准。

## 验收要点

- **PLAN-001～PLAN-002**：来源、任务变化、角色和交付标准可核对；分析不会直接变成正式任务。
- **PLAN-003**：缺失、失效或循环依赖被拒绝，必需与参考输入明确。
- **PLAN-004**：未决事项阻止直接及间接依赖它的实施工作；独立准备完成后，未决事项仍保留。
- **PLAN-005～PLAN-006**：参与者不能代替负责人；缺反馈、任一拒绝或依据变化均不应用。全部通过后整体生效，旧版同意不能用于新版，负责人交接不抹去有效决定。
- **PLAN-007**：纠正或移除推断后仍能查到原内容、理由和来源；原、新相关角色均审核，正式标准与真实未知事项不被擅自删除。
- **PLAN-008～009**：相关角色及理由可查；生效前先受理异议时仅该方案暂缓。回应未经提异议角色现任负责人确认不能放行，交接不自动结案；补角色或改方案后重审，生效后的异议转入问题或变更。
