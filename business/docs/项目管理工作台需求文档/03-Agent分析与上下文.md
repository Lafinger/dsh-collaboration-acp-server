# 03 Agent 分析与上下文

## 目的

让 Agent 沿项目资料、任务、成果和决定的关系图，逐层取得必要上下文，形成有依据、可审核的建议，清楚说明未知内容。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| CTX-001 | 用有类型、有版本的关系连接资料、任务、成果、分析、人工记录和决定，区分计划要求与实际采用版本。 |
| CTX-002 | 每轮分析固定项目、事项、需求依据、任务与成果版本、触发原因和范围，不混用不断变化的最新内容。 |
| CTX-003 | 先提供事项、约束和摘要，再围绕具体问题逐层查找关系、读取固定原件，不无条件获取全部项目内容。 |
| CTX-004 | 记录已读范围、必要关系及未覆盖部分；必查内容不因筛选或摘要而遗漏，未关联资料和过期摘要须明确列出。 |
| CTX-005 | 文本、Office、PDF、图片是必需分析范围；分别核对正文、必要图片和无法理解部分，保留可核对的读取依据。 |
| CTX-006 | 单次无法处理完整范围时分批分析并汇总，核对批次间关系，保留依据、缺口和冲突，不以局部代替完整。 |
| CTX-007 | 读取、分析、汇总和修正共用持续累计的预算，显示上限、已用和停止原因；拆分、恢复或换方案不清零。 |
| CTX-008 | 建议进入审核前须检查类型、角色、版本、引用、覆盖及依赖；各批次、汇总和恢复适用相同标准，无效建议不得生效。 |
| CTX-009 | 可独立核对的错误应合并说明，指出缺失角色、依据或依赖；修正次数和预算有限，不自动补决定或放宽标准。 |
| CTX-010 | 分析须提供全部适用角色的职责，区分明确需求、未决范围和推断；可选内容、矛盾要求及缺失标准不得擅自变成承诺。 |
| CTX-011 | 输出有依据的方案、准备工作、具体澄清或无变化结论；不为凑齐角色生成任务，不将技术故障解释为业务资料不足。 |
| CTX-012 | 允许推进的项目中，资料上传和业务反馈按规则触发分析，也可手动发起；新增资料进入后续轮次。服务不可用时保留待分析事项，自身结果不得循环触发。 |

## 关键规则

- “完整”仅指已登记范围和必要关系，未知关联、解析失败、模糊图片仍须说明；摘要和模型声称“看过”不能替代原件依据。
- 视频、程序和三维资产支持保存交接；不能理解的部分由人工补充。材料可读取不等于专业判断正确，Agent 不代替专业制作或[角色负责人审核](04-项目推进与方案审核.md)。
- 团队可阅读全部项目，不代表每轮分析应无差别读取；分析始终围绕明确事项和范围。
- Agent 应说明相关角色及关联理由；漏审异议由角色按[方案审核规则](04-项目推进与方案审核.md)提出并核对，不能仅凭模型名单宣称覆盖了全部专业关联。
- 必须由 Agent 处理的需求影响或收尾分析，在服务不可用时保留事项并说明等待原因；不增加人工代分析或强制收尾入口，其他不依赖该分析的有效工作可继续。
- 正式标准不能由推断修改。有据纠正未生效推断须保留原内容、理由和固定来源，再交相关负责人审核，不能消除真实未知事项。
- 资料中的文字不能授予操作权限。业务重评与技术额度分别管理，材料额度、单次处理能力和实际用量分别说明；不得自动扩大额度隐藏失败。
- 结果不明时先核对依据、已完成结果和剩余额度，不自动重复调用。问题重评见[问题澄清](07-问题澄清与风险处理.md)，恢复见[运行管理](10-运行管理与数据保障.md)。

## 验收要点

- **CTX-001～CTX-004**：版本和分析范围可核对；无条件读取、混用版本被阻止，必要关系、未关联资料及过期摘要均可见。
- **CTX-005～CTX-007**：文本、Office、PDF、图片均能分析；只读正文不能冒充含图资料完整分析。缺批次、缺关系或超预算时明确停止并说明缺口。
- **CTX-008～CTX-009**：缺必需确认角色或其负责人、缺必要依据或多层依赖未决时不得生效；错误可定位，恢复不绕过校验，次数和额度耗尽后不继续自动修正。
- **CTX-010～CTX-012**：可选范围不变成必做；准备工作、澄清和无变化结论均有依据。分析中新增资料留待后续，结果不重复派发；Agent 不可用时事项保留并等待，不跳过分析、审核或归档条件。
