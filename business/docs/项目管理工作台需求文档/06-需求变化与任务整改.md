# 06 需求变化与任务整改

[返回需求总览](README.md)

## 目的

在需求变化或成果整改时，重新核对受影响工作，保留旧版本和决定，避免过期方案继续生效。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| CHG-001 | 项目管理可登记顶层需求变化，保存变化内容、来源和影响范围。普通上传或概览编辑不代替正式登记。 |
| CHG-002 | 登记变化后，依赖旧需求的未生效方案与未结束评估应等待影响分析，不能继续按旧基准审核或应用。 |
| CHG-003 | Agent 根据固定需求版本和依据，提出“仍适用”“需要重新评估”或“无须推进”的结论，系统按规则处理并通知相关成员。 |
| CHG-004 | 新增、修改或取消已生效任务须经过方案审核。整改保留原任务身份，通过新版本重新处理，旧定义、成果和完成记录不变。 |
| CHG-005 | 任务升版后，重新核对输入与接收要求；结束已失效且未反馈的旧审核，保留已提交决定。已有上游成果也应生成所需接收待办。 |
| CHG-006 | 已产生成果的任务采用上游新版时，应逐项确认旧成果能否沿用：沿用须有检查依据，需整改须明确内容并进入任务升版流程。 |
| CHG-007 | 取消任务的方案须列出关联接收、新版审核及问题核对等义务。批准后，仅结束已无用途且尚未反馈的关联待办，保留已提交决定、其他使用者义务及问题和风险。 |

## 关键规则

| 影响结论 | 处理方式 |
| --- | --- |
| 仍适用 | 根据新需求重新核对方案并由相关角色重新审核，不复制旧同意；尚未形成方案的评估沿原事项继续。 |
| 需要重新评估 | 旧方案或评估轮次失效，沿原事项与原问题重新分析、审核。 |
| 无须推进 | 自动废弃受影响的未生效方案与未结束评估，结束未反馈审核，保留理由、已提交决定和历史。 |

- 不提供主动放弃方案、撤回成果或撤销接收。自动废弃只由正式登记的顶层需求变化及有依据的分析触发；信息不足应澄清，技术失败应修复，均不能视为“无须推进”。
- Agent 不可用或分析尚未完成时等待恢复，保留待处理事项；不以人工代分析、终止技术运行或归档绕过影响核对及方案审核。
- 取消任务不是完成任务。结束无用途的关联待办不自动解决问题或解除风险；仍有其他使用者或实际影响时继续处理，见[问题与风险](07-问题澄清与风险处理.md)。
- 已生效任务不因登记变化自动暂停。原问题、风险和累计分析用量继续保留；通知已读不表示审核通过。
- 处理中或已完成任务批准升版后重新进入处理中；旧完成结论不能代替新版完成。正式审核由全部相关角色的负责人分别决定，见[方案审核](04-项目推进与方案审核.md)。
- 采用新版与旧成果复核应完整提交后生效；原成果实际使用的输入不改写。仍适用的成果无需重复制作，需整改的成果按[成果交接规则](05-任务执行与成果交接.md)处理。

## 验收要点

- **CHG-001～002**：上传不会登记需求变化；正式登记立即阻止旧基准审核与应用，已生效任务保留。
- **CHG-003**：三种结论分别触发重新审核、重新评估或自动废弃；依据不足、技术失败及再次变化不造成误废弃，不清除问题、风险或用量记录。
- **CHG-004**：已完成任务整改后仍能查看旧完成版本；新版不得继承旧版完成结论，取消也须经过审核。
- **CHG-005**：输入要求变化后旧反馈不能用于新版；已有成果能生成新接收待办，无须再次发布。
- **CHG-006**：遗漏成果复核时不得部分采用新版；提交成功后可分别查到沿用依据、整改安排和原生成输入。
- **CHG-007**：取消方案未说明关联义务时不能完整应用；批准后只结束无用途的未反馈待办，其他使用者与已反馈历史不变，问题风险不自动结案。Agent 不可用时保留等待，不产生人工替代影响结论或自动归档。
