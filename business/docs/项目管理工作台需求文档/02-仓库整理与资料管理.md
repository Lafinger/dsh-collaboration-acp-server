# 02 仓库整理与资料管理

## 目的

按项目归集资料和成果，统一关联版本，方便团队查找、整理和交接，并保留原件及使用依据。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| MAT-001 | 按分派上传资料，明确项目、角色、提交人、原文件名、原相对路径、版本和用途；切换视角不改变归属。 |
| MAT-002 | 支持多文件、目录拖入及分次追加；提交前展示完整清单和相对路径，由提交人确认。 |
| MAT-003 | 区分传输完成、正式入库和失败；支持允许状态下的暂停、续传、重试与取消。 |
| MAT-004 | 同项目、角色和相对路径的冲突须明确处理；确认更新后形成新版本，保留旧内容和引用，不静默覆盖。 |
| MAT-005 | 不同角色或路径下的同名、同内容资料，分别保留登记身份和来源，不自动合并。 |
| MAT-006 | 支持目录浏览和路径筛选，显示归属与版本；普通资料上传与任务成果提交明确区分。 |
| MAT-007 | 提供支持格式的预览和原件下载；无法预览时说明原因，不显示为空文件。 |
| MAT-008 | 从任务、概览、建议或历史打开依据时，读取所绑定的固定版本并显示来源，不替换为最新同名文件。 |
| MAT-009 | 完整保存程序、三维等资产包；预览和整理不执行宏或资料内指令、不修改包内名称或路径。 |
| MAT-010 | Agent 对已登记资料提出分类、展示名称和逻辑目录的整理建议，说明理由及受影响角色，不自动整理外部仓库。 |
| MAT-011 | 全部受影响角色的负责人审核同一整理清单；全部同意且依据仍有效后整体生效，否则保留原结构并说明处理事项。 |
| MAT-012 | 整理只改变展示结构并保留前后差异，不改变原件、角色归属、任务关系、成果身份和历史引用。 |
| MAT-013 | 正式入库时重新核对提交人的资格、分派及项目是否允许写入；已停权或已归档后的迟到上传不得自动入库。 |

## 关键规则

- 原相对路径说明来源，固定版本用于核对，逻辑目录和展示名称方便查找；三者不能混用。
- 同批和跨批同路径冲突均须处理；跨路径同名不视为冲突。续传须确认内容未变，已用于业务提交的文件不得随上传取消或过期而删除。
- 团队可查阅全部项目资料；上传、更新和整理决定按职责分派。参与者可讨论，负责人代表角色正式审核；角色遗漏按[补审规则](04-项目推进与方案审核.md)处理。
- 交接不冒用原提交人的身份继续写入。接任者可明确接续已保存材料，保留贡献人及来源；未纳入完整成果提交的文件不自动完成任务。入库与归档的先后按[运行保障](10-运行管理与数据保障.md)核对。
- 文本、Office、PDF、图片应支持分析；视频、程序和三维资产可保存交接。无法理解的内容须说明并由人工补充，见[Agent 分析](03-Agent分析与上下文.md)。
- 损坏、加密、不支持或超限须说明原因并保留原件下载。普通上传不完成任务；原件和固定引用的保留规则见[历史追溯](09-历史追溯.md)。

## 验收要点

- **MAT-001～MAT-003**：多文件和目录可追加，归属与清单正确；续传不混入已变化内容，传输完成不误报入库成功。
- **MAT-004～MAT-005**：同路径更新需确认，新旧版本可查；跨角色或路径的同名资料保持独立。
- **MAT-006～MAT-009**：可按目录查找；上传不完成任务，预览失败仍可下载；同名更新后历史依据不变，资产包保持原样。
- **MAT-010～MAT-012**：参与者不能代替负责人批准；少一份同意或依据变化均不生效。通过后差异可查，原件、归属、业务关系和历史引用不变。
- **MAT-013**：上传期间停权、改派或归档后，迟到结果不自动入库；接任者明确接续材料时，原贡献人仍可查。
