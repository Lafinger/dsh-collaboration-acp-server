# 05 任务执行与成果交接

## 目的

明确使用什么、完成什么、交给谁；负责人确认完成，下游负责人独立接收，系统生成交接待办并保留依据。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| TASK-001 | 展示项目、责任角色、主执行人、协作者、当前版本、工作要求、输入、必交成果和完成标准，旧版本可追溯。 |
| TASK-002 | 必需输入关联上游成果与固定接收标准，经下游负责人独立接收具体版本后才可执行；参考输入不阻塞开始。 |
| TASK-003 | 按分派保存非空文字或文件进展，可多次追加；保存进展不完成任务或驱动下游。 |
| TASK-004 | 主执行人汇总成员贡献，按成果要求提交明确版本的说明、文件和自检；支持多文件、目录及本角色已登记资料复用，保留来源与实际贡献人。 |
| TASK-005 | 负责人确认完成前，系统核验当前版本、必交成果、自检、实际输入、文件完整性及未解决的阻塞；不足时拒绝并说明原因。 |
| TASK-006 | 负责人确认完成成功后，一次保存完成记录、固定成果版本并生成接收待办；重试和中断不造成半完成或重复交接。 |
| TASK-007 | 需提前交接的阶段成果拆为独立任务，完整完成并被接收后才驱动下游；新增输入引用已有成果也须首次接收。 |
| TASK-008 | 首次接收可接收或拒收；新版可采用、说明沿用旧版或拒收，各下游任务由责任角色负责人分别核对固定标准并决定。 |
| TASK-009 | 同一输入连续新版须合并尚未反馈的同类接收待办并更新目标，保留历史，旧表单失效；不得吞掉独立的问题复核。 |
| TASK-010 | 采用新版须逐项确认既有成果仍适用或需要整改，与采用决定一并提交；复核不全不能放行完成和交接。 |
| TASK-011 | 等待接收审核时可按已接收旧版保存进展，暂缓完成和新交接，显示原因及处理入口。 |
| TASK-012 | 完成后整改须经方案审核形成同一任务的新版本，保留旧完成记录、成果和实际输入。 |
| TASK-013 | 每项执行任务有一名主执行人，可分派协作者；协作者提交贡献，主执行人汇总。主执行人更换须明确交接未完工作和已提交内容，保留原贡献与决定。 |
| TASK-014 | 所属角色负责人核对主执行人提交的固定成果和自检版本，可确认完成或说明不足并退回；确认期间新增内容不得自动混入已核对的提交。 |

## 关键规则

- 成员负责专业制作和自检，主执行人汇总后由负责人代表角色确认完成，不另设审核层级；主执行人提交本身不完成任务、不生成下游接收。下游独立接收，文件齐全不等于质量合格。
- 内部退回表示当前提交尚不合格，任务保持未完成，由主执行人组织补充并重新提交；不等于下游拒收，也不生成完成或交接结果。
- 确认仅针对已提交并核对的版本。新增贡献或更新须明确提交并重新核对，不能借旧确认将未核对内容作为完成成果。人员交接按[项目与角色管理](01-项目与角色管理.md)办理，不改变历史贡献。
- 新版不自动替换已接收输入或改变标准。待办首次接收随新版更新；计划已指定首次版本时，先处理指定版本。
- 每次发布正式新版，应向直接使用者生成变更审核待办；下游自身成果变化后，再推动下一层审核。严重风险按[问题与风险规则](07-问题澄清与风险处理.md)追踪跨层影响。
- 拒收可结束本次审核，但不满足输入要求，也不撤销其他下游的接收。保存进展、确认完成和成果接收不能互相替代。
- 不撤回成果或撤销接收，以新版及后续决定纠错。采用新版后旧成果仍适用时，保留复核理由和原标准检查，不伪造新成果或改写原输入。
- 职责、范围、标准、依赖和整改须按[需求变化](06-需求变化与任务整改.md)审核；进展文字不能隐式改动。

## 验收要点

- **TASK-001～TASK-003**：分派与标准可查；必需输入未接收不能执行，保存进展不完成任务。
- **TASK-004～TASK-007**：缺成果、自检不全或文件损坏均不能确认完成；主执行人提交本身不完成任务，负责人确认完成成功后只产生一份完成事实和必要待办，阶段任务接收后才推动下游。
- **TASK-008～TASK-009**：各下游独立决定；连续新版更新待审目标并保留历史，旧表单失效，遵守指定首次版本，保留问题复核。
- **TASK-010～TASK-011**：遗漏任一适用性复核时不能切换输入并放行；等待期间可保存进展，负责人独立接收。
- **TASK-012**：整改后仍可查看旧版完成事实与实际输入，新版不能继承旧版完成结论。
- **TASK-013～014**：每项任务只有一名主执行人，协作贡献与交接可查；内部退回不完成或交接任务。确认期间追加、更新文件不混入已核对版本，重新提交后须再次核对。
