## 全局性删除（适用于全部模块）

以下 4 类内容在原文档中贯穿所有模块，MVP **整体删除**，因此下文不再逐条重复说明：

| # | 删除内容 | 理由 |
| --- | --- | --- |
| G1 | 全部**权限体系与认证**（停权、接任、任命、代表权、登录、账号、凭据） | 已确认"完全不考虑权限和安全问题"；九角色降为标签。**注意**：MVP 保留一项**成员资格校验**，它**不属于**权限体系——见文末变更记录 |
| G2 | 全部**人员交接**语义（交接清单、候任确认、承接未办） | 无权限则无"职责转移"；MVP 为单机/单调用方 |
| G3 | 全部**管理凭据/敏感信息保护** | 随权限一并删除 |
| G4 | 全部**配额/预算上限/用量强制**（记录保留，上限不设） | 运维能力，与主链路无关 |
| G5 | 全部**界面/键盘/屏幕适配**要求 | MVP 无界面 |

## 变更记录

### 2026-10-11 · 恢复轻量成员资格校验（G1 收窄）

**改了什么**

原 G1 写的是"全部**权限/身份/任职校验**整体删除"，正文据此有多处写着"不做身份与任职校验""系统不校验身份""不做校验"。
现在改为：**权限体系与认证仍然全部不做**，但新增一项**成员资格校验**——代表某个角色做决定（方案确认、成果复核、成果接收）时，
**会话声明的身份必须是该角色槽位的成员**，否则拒绝。

**为什么改**

原文依据的是"完全不考虑权限和安全问题"，而那句判断成立的前提是**单用户桌面使用**：只有一个人，校验没有对象。
一旦变成**多成员客户端各自接入**（见 [ACP 独立运行时方案](ACP独立运行时方案.md)），"不校验身份"就产生一个原文没预料到的后果：

> 任何成员都能以任何角色名义确认。一个客户端提交九次、填九个名字，"全部相关角色均已同意"就被架空了。

而原文本来要防的正是"一次确认顶多个角色"。**不绑定身份，这条防线就只在"同一个人"这一种情况下成立，换个人即失效。**
实际使用中已经出现过：Agent 编造出九个不存在的成员名填满确认槽位，确认记录变成虚构。

**这不是恢复权限**

两者的界限（也是本次改写采用的口径）：

| | 做不做 | 内容 |
| --- | --- | --- |
| **认证**（你是谁） | ❌ 不做 | 登录、账号、密码、凭据 |
| **授权体系**（你能管什么） | ❌ 不做 | 任命、接任、停用、代表权、管理员资格交接、角色等级 |
| **成员资格**（这个决定是否来自该角色的人） | ✅ **做** | 声明的会话身份 == 该角色槽位的成员 |

**成员资格校验不是安全机制**：身份是**会话内自我声明**的，系统**不验证**说话的人是否真是他自称的那个。
它做到的是——记录不再可以是编造的、角色之间不能互相顶替；它做不到的是——拦住一个故意冒名的客户端（那需要认证，仍然不做）。

**影响**

- `MVP-004`、`MVP-019` 的文字已相应改写；"MVP 需求 → 完整版需求 映射摘要"中 `MVP-001~005` 行已更新。
- `G1`、`PRJ-006`、`PRJ-008` 的判断理由收窄到"权限体系"，不再声称删除成员校验。
- `README.md`（"明确不做"表、与完整版差异表）、`GLOSSARY.md`（成员快照）、`docs/adr/0004` 的连带表述已同步。
- **上文"恢复顺序"第 3 批不变**：`PRJ-009/011/012/013/014`（任命、任免权、接任确认、停权、管理员资格交接）**仍然不做**。
  本次只是从第 3 批里**提前取出了最小的一块**，整批权限与组织设计仍然后置。
