# 01 项目与角色管理

[返回需求总览](README.md)

## 目的

让团队清楚项目目标、成员、职责与进展；人员变动有明确交接，管理缺位不越权，项目结束后历史仍可查。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| PRJ-001 | 管理员可创建项目，登记名称、标识和启用角色，并指定项目管理负责人接任。背景和目标未明确时显示待补充。 |
| PRJ-002 | 使用下表九类专业角色，按需启用或停用；启用须落实负责人，停用前处理相关责任。项目管理职责在项目存续期间保留。 |
| PRJ-003 | 成员可查看团队全部项目，按项目、角色或个人分工找到工作；切换范围不混用文件、表单和决定。 |
| PRJ-004 | 概览展示背景、目标、角色状态、进展和正式计划。项目管理维护概览，其他成员可读；编辑说明不改变正式范围。 |
| PRJ-005 | 分别说明场景模型、场景美术和 UE端是否需要参与及其依据；未确定时标为待判定，缺所需角色时提示落实责任。 |
| PRJ-006 | 管理员管理成员身份和使用资格；停权、退出后不得继续使用原资格。记录实际成员及当时职责，不删除其历史。 |
| PRJ-007 | 项目管理负责人分配角色参与者及任务主执行人、协作者，具体规则见[任务执行](05-任务执行与成果交接.md)。一人可兼多角，一角可有多人，但同时只有一名有效负责人。 |
| PRJ-008 | 项目业务公开可读，写入按分派授权；正式审核、接收和确认由对应负责人提交，并在生效时核对身份、任职和权限。管理凭据不公开。 |
| PRJ-009 | 正常退出、更换负责人或停用角色前，列明在办任务、审核及问题风险责任并完成交接；新任承接未办事项，旧有效决定及实际操作者保持不变。 |
| PRJ-010 | 项目管理负责人可归档并主动恢复项目。归档前完成交付或获批停止，清结在办事项、问题和风险；归档业务只读、停止推进，恢复时重新核对处理条件。 |
| PRJ-011 | 管理员任免项目管理负责人；项目管理负责人任免其他专业负责人。参与者没有任免权，管理员身份不授予专业审核权。 |
| PRJ-012 | 新任须查看在办清单并确认后才接任；确认前原任资格有效则继续履职，已停权则相关处理等待。候任者可确认指定的管理交接，无须预先拥有该职责的业务权限。 |
| PRJ-013 | 紧急情况可先停权、后补交接，无须失联或不可用原任同意。按任免层级落实接任者；空缺期间不自动通过审核，也不由无权成员代办。 |
| PRJ-014 | 管理员资格只能由可用的现任管理员交接，新任同样须确认接任；正常退出前须已有可用接任。全部管理员均无法使用或恢复管理资格时，须管理员权限的相应操作停用，未生效的管理员接任也暂停，不另设恢复人。 |
| PRJ-015 | 归档须列全未结事项，并在生效时复核：执行与审核、成果接收、需求影响、资料整理、问题风险、责任交接、排队或未结束的分析、结果不明操作，以及上传和入库。任一未妥善结束均不能归档。 |

## 关键规则

### 九类专业角色

| 角色 | 职责与主要成果 |
| --- | --- |
| 项目管理 | 整理需求、把控进度、组织协作和统一交付。 |
| 产品 | 细化需求，设计交互流程与原型。 |
| 设计 | 基于产品成果完成 UI 风格与视觉设计。 |
| 场景模型 | 完成建模、拓扑、UV 和模型资产。 |
| 场景美术 | 完成场景搭建、材质、灯光和整体视觉。 |
| 数据 | 整理项目数据，制作所需数据成果。 |
| 前端 | 开发网页 UI、接入后端服务，交付网页服务程序及其测试运维成果。 |
| 后端 | 开发数据接口，交付接口服务程序及其测试运维成果。 |
| UE端 | 集成网页、接口、模型和场景，开发交互，交付 Unreal Engine 打包程序及其测试运维成果。 |

- **一角一名代表。** 参与者执行、讨论和提交成果，负责人作正式决定；兼任者分别记录各角色决定。临时代行也按负责人交接办理，不同时保留两名有效负责人。
- **接任不重写历史。** 指定候任者不立即撤换有效原任；接任生效后原任失去相应代表权。停权或交接后的旧页面不能提交新决定，此前有效决定不因换人失效。
- **停用不删专业责任。** 职责变化按[方案审核](04-项目推进与方案审核.md)处理，不能删除原问题的必需确认角色或交给项目管理代批。历史义务再次出现时，重新启用所需角色并落实负责人。
- **概览与计划分开。** Agent 提出的概览随方案审核生效；真实范围变化按[变更流程](06-需求变化与任务整改.md)登记，所需责任未落实时方案不能生效。
- **结束方式如实记录。** 成功交付与批准停止分别记录；批准停止不等于成果合格，归档不替代验收、问题关闭或[风险处理](07-问题澄清与风险处理.md)，不永久删除项目。
- **归档保留必要管理。** 仍可阅读、记录个人已读及办理管理交接，不能新增或修改业务内容。未读通知不算未结业务；发现新问题先在团队沟通，由项目管理负责人主动恢复后正式登记，不增设恢复申请入口。

## 验收要点

- **PRJ-001**：管理员创建项目并指定项目管理接任，未明确的背景与目标不被编造。
- **PRJ-002**：只启用九类角色，落实负责人；停用不能遗留专业责任，历史义务再现时重新启用。
- **PRJ-003**：可读其他项目，切换后不串用文件或表单。
- **PRJ-004**：概览可查，越权编辑被拒绝；改说明不改变正式计划。
- **PRJ-005**：三维职责判定有依据；未确定或缺角色时提示处理。
- **PRJ-006**：停权和退出后原资格不可继续使用，历史仍记录实际成员。
- **PRJ-007**：主执行人与协作者明确，一人兼任记录可辨；同一角色不能出现两名有效负责人。
- **PRJ-008**：生效前失去权限的提交被拒绝；参与者不能作负责人决定，管理凭据不可公开读取。
- **PRJ-009**：正常交接覆盖任务、审核、问题与风险，未办由新任承接，旧决定不重审或改名。
- **PRJ-010**：分别核对交付和批准停止的结束记录；归档不关闭风险。归档后业务只读，但阅读、已读与管理交接可用；只有项目管理负责人主动恢复后才能登记新问题。
- **PRJ-011**：管理员可任免项目管理负责人，项目管理负责人可任免其他负责人；参与者任免及管理员直接代审被拒绝。
- **PRJ-012**：新任能在无该职责业务权限时查看清单并确认接任；确认前有效原任可继续、停权原任不可继续，确认后仅新任具有代表权。
- **PRJ-013**：原任失联时可立即停权并补办交接；未接任前相关正式处理等待，不依赖原任同意或自动批准。
- **PRJ-014**：普通成员不能恢复管理员资格；正常管理员退出须先有可用接任，全部不可用时不开放须管理员权限的操作，候任身份也不能恢复管理权；不冻结仍有权限的项目管理或专业工作。
- **PRJ-015**：未处理上传、排队或挂起分析、结果不明操作及业务待办均阻止归档；核对期间新增未结事项也不能遗漏，单纯未读通知不阻止归档。
