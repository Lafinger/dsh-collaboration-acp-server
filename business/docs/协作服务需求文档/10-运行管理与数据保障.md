# 10 运行管理与数据保障

[返回需求总览](README.md)

## 目的

让团队了解真实运行情况，保护业务数据，并在失败、中断或恢复后明确哪些操作已生效、下一步如何处理。

## 核心需求

| 编号 | 需求 |
| --- | --- |
| OPS-001 | 管理员可配置模型服务与连接信息，区分默认设置和当前分析使用的设置；模型测试应说明实际验证的能力，文本成功不代表能识别图片。 |
| OPS-002 | 运行概况应展示项目、运行、排队、挂起和近期处理趋势；等待人工反馈单独统计，不冒充模型繁忙。 |
| OPS-003 | 监控应按项目关联问题、评估与分析轮次，展示实际过程、用量和错误原因；未知信息明确标记，不补造记录。 |
| OPS-004 | 停止运行应保留可恢复状态，并与终止区分；恢复前核对原结果和依据，保留历史及累计用量。 |
| OPS-005 | 耗时分析不应阻塞成员保存业务信息；服务暂不可用时保留排队事项。模型测试与业务分析应有序调度，不丢失或突然中止正在进行的请求。 |
| OPS-006 | 请求未发出、模型失败、结果不合格、修正失败和结果不明应分别提示，给出可定位的原因与处理入口。 |
| OPS-007 | 正式操作应完整生效；重复提交不产生重复结果，内容或版本冲突明确拒绝，未提交完整的信息不得推动后续工作。 |
| OPS-008 | 中断恢复应核对文件、业务结果和运行记录，只补齐缺失步骤；不明模型结果须先核对，不自动重复调用或清除用量。 |
| OPS-009 | 备份应完整保存原件、成果、版本、决定及推进所需记录，并核验一致性；展示备份范围、未包含的信息与失败原因。 |
| OPS-010 | 恢复前应检查备份兼容性、完整性与目标范围，保护现有数据；恢复后先核验，再明确开启业务推进，不自动重放不明操作。 |
| OPS-012 | 关键内容与操作应适应不同屏幕尺寸并支持键盘；列表、详情和操作区可完整到达，禁用状态清楚。 |
| OPS-013 | 上传、读取、预览、分析和恢复应检查文件来源、所属项目、固定版本与资源限制；不得越界操作、执行材料中的恶意内容或将材料文字当作操作授权。 |
| OPS-014 | 成员操作须在正式生效时核对身份、分派与角色职责，不能只按打开表单时的资格处理；仅授权管理人员可维护配置，凭据不向普通业务阅读、分析材料或日志公开。 |
| OPS-015 | 归档的最后核对与停止业务写入须形成一致结果；并发提交有明确先后，不能出现已归档项目又新增正式业务的情况。 |
| OPS-016 | 恢复业务备份不得恢复已撤销的成员资格、负责人权限或旧访问凭据；开放操作前核对当前有效身份及任职，历史身份与当前授权分开。 |

## 关键规则

- [项目角色与权限](01-项目与角色管理.md)决定谁能操作；切换视角或拥有管理员身份不能替代专业审核。
- 正式结果已保存但页面未更新时，只恢复显示和后续处理，不重复完成任务、分派审核或调用模型；迟到结果须确认仍适用才能生效。停权或换任后旧请求不能取得新的业务效果，但不抹除停权前已正式生效的结果。
- 归档前核对排队、运行、挂起、上传及未入库材料，不能只查可见待办。先于归档生效的提交纳入检查；后到结果仅保留必要的技术诊断，不得入库、生成方案或待办、触发分析。恢复后重新核对，不自动重放。
- 暂停分析不等于等待人工反馈；终止技术运行不等于放弃业务方案。问题仍按[累计分析规则](07-问题澄清与风险处理.md)处理。
- 备份除文件外，还须包含审核、接收、上传、运行、用量和个人已读等恢复所需记录。涉及敏感配置的范围及保护方式应单独说明。
- 备份与恢复期间不得形成互相矛盾的数据。检查失败应停止并说明原因，不能跳过校验宣布成功。
- 恢复后对照当前有效成员及负责人核验权限，个人已读状态仍归原接收人。缺少可信身份或任职依据时保持暂停，由有权管理员核验，不按姓名自动匹配或让普通成员提权。
- 管理员任职交接按[项目与角色规则](01-项目与角色管理.md)办理；全部管理员不可用时，须管理员权限的相应操作保持停用，不设额外恢复人；项目管理及专业角色已有的有效权限不受此限制。必须由 Agent 分析的事项在其不可用时等待恢复，不用人工收尾绕过。
- 归档停止业务推进，阅读、个人已读和管理性交接仍可办理；恢复由项目管理负责人明确发起，并核对人员、版本与运行结果。本模块不提供永久删除项目或清空团队业务数据的要求。

## 验收要点

- **OPS-001～006**：配置缺失、服务不可用、额度不足和结果错误分别可辨；停止可核对恢复，终止保留历史，待反馈不计为模型执行。
- **OPS-007～008**：提交或模型处理时中断，恢复后无半完成任务、重复审核或未经核对的重复调用；不同成员同时修改同一版本时明确提示冲突。
- **OPS-009～010**：备份不一致不能报告成功；不兼容或不完整恢复被阻止，现有数据受保护，核验完成前不自动推进。
- **OPS-012～014**：键盘和小屏能到达关键操作；恶意材料、越界引用及无权操作被拒绝。打开表单后发生停权或换任，旧提交不能生效；原已生效决定仍保留。
- **OPS-015**：最后检查与上传完成、模型返回、新请求并发时，归档结果一致；归档后无新正式业务或自动分析，恢复不重放不明结果。
- **OPS-016**：恢复旧备份不使已撤销身份、旧负责人或旧凭据重新有效；无可信核验依据时暂停。全部管理员不可用时仅停用须管理员权限的相应操作，不授权普通成员或未接任候任者接管，不停止其他已有授权的工作。
