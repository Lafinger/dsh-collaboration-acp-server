# 被否决的提案

记录**没有采纳**的设计提案，以及否决的理由。

它和 ADR 的区别：ADR 记**做过的决定**，这里记**没做的决定**。同样值得留档 —— 因为否决一个新提案，往往要靠几条**查证成本很高的事实**，不写下来，下次会重新查一遍，甚至重新踩同一个坑。

---

## 提案一：工具门禁（必须说 `@项目助手` 才能调工具）

**提出时间**：MVP 完成之后
**否决时间**：同轮讨论结束时
**状态**：**已否决，不实现**

### 原始诉求

> "我不希望该插件里面的工具默认可以调用，我希望是需要出现 `^项目助手` 之类的关键词才能调用工具。"

经过三轮澄清，最终定义是：

- **触发词**：完整出现 `@项目助手`
- **粒度**：每轮重锁（上一条消息说了，这条没说就重新锁上）
- **判定范围**：只看最后一条真实用户消息（`source.kind === 'user'`）
- **可见性**：工具照常注册，调用时由守卫拒绝
- **默认值**：默认开启

### 否决理由

**根本原因：这不是需求。** 用户的原话：

> "我想清楚了，这不该是需求，**模型应该自主调用才对，用户应该是无感的**。"

随后用户进一步澄清了"无感"的确切范围：

> "我澄清一下『无感』，指的是：**模型会自动调用相关工具不需要关键词**。"

**这个澄清很重要，因为它把范围收窄了。** "无感"在本语境下只指**不用关键词**这一件事：

- **是**：模型自动挑工具，人不用念咒语
- **不是**：模型主动提醒下一步（需要新的触发时机，属另一需求）
- **不是**：模型自行推进项目（需要调度器，ADR-0005 已排除）

**人仍然要开口**说「建个项目」「看看待办」—— 无感的是"不用念咒语"，**不是"不用说话"**。

诉求由此**反转**：原提案要"加一道授权"，而真实意图是"**根本不该有授权这一层**"。反转后落成 **MVP-033**（模型自主调用、不用关键词）。

### 三条查证事实（否决的技术依据）

这些是查证 DSH 源码与 `@deepseek-ai/dsh-tools@0.1.5-rc.2` 类型定义得到的，**不是推测**：

**① `restrict()` 做不到"每轮翻转"。**

```
Restrict global tools for the calling agent scope. Empty filters, unknown
names, scope-local names, and reserved transport names fail. Restrictions
intersect; scoped registrations remain visible.
                                                    —— dsh-tools/lib/types/index.d.ts:603
```

它是**会话级的静态可见性收缩**，没有"这一轮缩小、下一轮放开"的时间维度。所以"**隐藏** + 每轮重锁"这个组合，**DSH 没有现成机制支持**。

**② 想做每轮重锁，只能"看得到但调了报错"。**

| 机制 | 作用点 | 能否每轮翻转 |
| --- | --- | --- |
| `restrict({allow, deny})` | 工具清单（模型看不到） | **否**，会话级静态 |
| `guard(fn)` | 调用前（返回字符串即拒绝） | **能** |
| `tools/pre-execute` | 调用前（瀑布，可 allow/deny/ask） | **能** |

用 `guard` 就意味着**模型看得到工具**，它会反复试探，每次被拒都浪费一轮调用。

**③ `guard` 读得到对话，但这是"能做"而非"该做"。**

`guard` 收到的 `exec.agent` 上有 `agent.session`，而 `deriveMessages()` 是**同步且增量缓存**的：

```js
deriveMessages() {                       // dsh-session/lib/index.js:1554
  const surface = this.surface;
  const nodes = surface.nodes;
  const generation = surface.contentGeneration;
  if (generation !== this.derivedGeneration) { /* reset */ }
  for (const seq of nodes.slice(this.derivedNodes)) { /* only new nodes */ }
  return [...this.derived];
}
```

所以**技术上完全可行**。否决**不是因为做不到**。

**④ 门禁全开或全关，拦不住真正想拦的事。**

人打一次触发词，**所有**工具全部放开 —— 包括 `plan_revise`、`result_accept`、`project_archive` 这类**改数据**的。人打触发词可能只是想查待办，却同时授权了改任何东西。

**真要防误操作，需要的是「只读模式」**（本次讨论中识别为一个**独立需求**，未展开）。

### 相关：`@` 在 DSH 里安全吗（查证结论）

**安全。** 三层查证：

| 查了什么 | 结论 |
| --- | --- |
| 运行时（服务端）有无 `@`-mention 解析 | 没有 |
| 客户端 `mention` 命中 | 全在 **PDF 阅读器**里 |
| `startsWith("@")` 的 9 处用法 | 全是**文件/文件夹引用的高亮**，`kind` 仅 `session`/`file`/`folder` |
| 发送时是否改写文本 | **不改写** —— 客户端只做自己的显示装饰 |

**唯一例外**：若 `项目助手` 恰好匹配到某个文件名、且用户**从补全里主动选中**，会变成文件引用。正常打字不会触发。

### 如果将来要做，怎么做

1. 先读 **MVP-033** 与 **ADR-0005 的「边界」一节**，确认需求确实变了
2. 用 `ctx.tools.guard()`，**不要**用 `restrict()`（后者做不到每轮）
3. 触发判定：`agent.session.deriveMessages()` → 倒序找 `role === 'user'` 的项 → 过滤 `source.kind === 'user'`
4. 拒绝文案必须**可执行 + 明令禁止重试和编造** —— 模型看不到自己为什么失败时会倾向于编造结果
5. 写 ACP 冒烟脚本**实测**"没触发被拒"和"触发后能调" —— 上述结论**全部来自读源码，未跑过一行代码**

### 顺带澄清的一个词义问题

`@项目助手` 曾同时表示**插件包名**和**会话内触发名**。这是**一词两义**，也是本次讨论绕弯的源头之一。现已拆分：

- **`@项目助手`** = 包名
- **会话内称呼** = 随口叫它什么都行，**与工具能否调用无关**
