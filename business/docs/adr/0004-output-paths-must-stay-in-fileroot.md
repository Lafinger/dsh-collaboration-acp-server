# 输出路径必须约束在 fileRoot 内

状态：已采用

写入文件前**必须**校验目标路径仍在 `fileRoot` 之内，`project_id` 与 `role` 都要参与校验：

```
target = resolve(fileRoot, ...parts)
rel = relative(fileRoot, target)
if (rel.startsWith('..') || isAbsolute(rel)) throw PATH_ESCAPES_FILE_ROOT
```

## 为什么

`project_id` 与 `role` 会被拼进输出路径。实测确认：构造 `project_id = ../../../../ESCAPED` 能**真实把文件写出 `fileRoot`**（已在实际磁盘上复现并清理）。

两个加重情节：

1. **`path.join` 不防穿越**——它只负责拼接，`..` 原样保留。
2. **`path.relative` 遇到越界不报错**——静默返回 `..\..\` 开头的相对路径。因此"存相对路径"这个设计**本身不会发现越界**；朴素的 `startsWith('..')` 检查若发生在 `copyFileSync` 之后，**写已经发生了**。

## 值得记录的取舍

这条 ADR 的价值在于**它看似与"MVP 不考虑权限安全"矛盾**。

`ADR-0003` 明确接受了一个风险：`source_path` 可以指向任意位置，任何调用方都能读机器上的任意文件。**这是有意为之的取舍**。

那么为什么输出路径要额外约束？因为两件事性质不同：

| | `source_path` | 输出路径 |
| --- | --- | --- |
| 语义 | **读哪里** | **写哪里** |
| 后果 | 读到不该读的内容 | **覆盖或污染不该动的文件** |
| 取舍 | 已接受（无权限） | **不接受** |

读一个文件是**可撤销的**（内容没变）；写到错误位置是**可能不可撤销的**（覆盖了别人的文件）。而且穿越来自**内部生成的路径成分**（`project_id`/`role`），不是调用方显式给出的路径——调用方甚至没意识到自己在写文件。

**替代方案**：什么都不做，靠"单人本地使用"兜底。否掉的理由是修复成本只有一个函数，而后果是静默污染 `fileRoot` 之外的目录。

## 后果

- **校验必须覆盖所有路径成分**，只校验 `source_path` 不够——穿越来自输出路径的组成部分。
- **校验必须在写入之前**。事后检查等于没检查。
- 这条约束**不依赖权限模型**，因此与 ADR-0002/0004（角色是标签、不做权限校验）不冲突：它约束的是**程序自身的行为**，不是调用方的资格。
- 同一模式的校验应施加于**所有**由外部输入拼接出的文件路径（未来若增加导出、快照等功能）。
