# 没有调度器：推进由人发起

状态：已采用

MVP **不实现"Agent 自动推进项目"的调度器**。发起下一轮工作（请求分析、登记方案、催办）**只能由人触发**；Agent 可以建议下一步做什么，但不会自行启动。

## 为什么

最初的需求描述是"构建 Agent 能结合仓库所有材料**不断推进**项目的**内循环**，直到项目结束"。这听起来像要一个自主循环。但 MVP 已有两条需求**直接禁止**它：

- **MVP-016**：分析结果只是建议，**不自动**成为正式计划、**不自动**创建任务、**不自动**消除未决事项
- **MVP-027**：拒收**只产生一条记录和一条通知**，不自动触发任何后续流程

若 Agent 能自动派活，**建议就变成了任务**——M4 的整套确认门禁（多角色确认、角色空缺阻塞、确认作废保留）形同虚设，因为 Agent 可以绕过它直接下发工作。

## 关键认识

**"内循环"其实已经存在**，只是分散在几个模块里：

```
分析 → 建议 → [人登记方案] → 各角色确认 → 正式计划
  → 任务 → 角色交成果 → 角色确认完成 → 下游接收 → 新待办
  → （人看到待办）→ 发起下一轮分析 → …
```

这条链**不缺机制，缺的是"谁在何时发起下一轮"**。而 MVP-016/027 已经回答了：**是人**。

所以本 ADR 不是"砍掉一个功能"，而是**确认一条本来就隐含在需求里的边界**，并明确它是有意为之。

## 排除的方案

**Agent 自动派活（真正的自主循环）。** 否掉的理由不是"太难"，而是**它会推翻 MVP 唯一的硬机制**。要它成立，必须先改写 MVP-016 与 MVP-027，那等于把"建议不具约束力"这条核心规则删掉。

**Agent 提议 + 走确认门禁后自动生效。** 这个其实**可行**，但它在 MVP 里**不需要新机制**：那就是"人登记方案"的一次普通使用。Agent 提议、人确认并登记、各角色确认——**没有任何一步是自动的**。因此不实现额外的调度逻辑。

## 后果

- **不需要调度器、定时器、队列或状态机**。省掉的是整个 MVP 里最复杂、最难测的一块。
- 数据模型里**没有"下一步动作"这类字段**，也没有"循环轮次"。
- Agent 的价值集中在**一次分析做得好**，以及**能让人看清该发起什么**（先看目录、再圈范围）。
- **"结合仓库所有材料"落到实现上 = 读所有材料的目录**（`material_list` 已实现），**不是**把所有内容塞进上下文。内容必须逐次显式圈定（MVP-013）。
- 将来若要做自主循环，这是一次**明确的需求变更**，需要同时修订 MVP-016/027 ——**这是好事**：边界清晰，不会悄悄越界。

## 边界：「人发起」不等于「人念咒语」

这条 ADR 容易被误读成"人在场时还得先做点什么来授权"。**不是。**

**"人发起"指人开口表达意图，不指人先解锁工具。** 人说完「帮我建个项目」，**Agent 自己决定调哪个工具、调几次** —— 这是预期行为，**不需要任何额外的触发词、暗号或显式授权**。

用户对"无感"的定义（原话）：**"模型会自动调用相关工具，不需要关键词。"** 范围**仅此而已** —— 人仍然要开口说「建个项目」「看看待办」，**无感的是不用念咒语，不是不用说话**。

两者的区别：

| | 谁决定 | 本文档的规定 |
| --- | --- | --- |
| **要不要推进这个项目** | **人** | 由人发起（本 ADR） |
| **这一次用哪个工具去推进** | **Agent** | 完全自主，无需授权（MVP-033） |

**这条边界是有意划下的，且曾被明确否决过反向提案**：曾有"必须用户输入 `@项目助手` 才允许调用工具"的需求提案，理由是防止 Agent 乱调工具。**它被否掉了**，原因见下。

### 为什么否决工具门禁

1. **它和本 ADR 的精神相反。** 本 ADR 排除的是"Agent 自行启动下一轮"，**从未**要求"人先授权工具"。加门禁等于凭空引入第三层，而需求里没有它。
2. **DSH 做不到"每轮隐藏"。** `ctx.tools.restrict()` 是**会话级的静态可见性收缩**，没有"这一轮缩小、下一轮放开"的概念。想做"每轮重锁"只能用 `guard` 在调用时拒绝 —— 那就变成**模型看得到、调了报错**，它会反复试探并浪费调用。
3. **门禁是全开或全关，拦不住真正想拦的事。** 人打一次触发词，**所有**工具（含 `plan_revise`、`project_archive` 这类改数据的）全部放开。真要防误操作，需要的是**只读模式**，那是另一个需求，不是触发词。

**将来若有人再次提议门禁**，请先读这三条，以及 **MVP-033**。
