## 1. 唯一目标与最小闭环

普通成员只需在DSH填写服务地址，用电脑钉钉确认身份，随后选择项目开展协作。管理员用相同身份登录，在DSH创建项目并从已登录成员中分配角色，不管理个人SSH账号、公钥或项目参与名单。

```text
管理员／成员安装客户端插件 → 填一个HTTPS服务地址
  → DSH发起登录 → 电脑钉钉内完成官方身份确认
  → 原DSH自动取得登录结果 → 首次身份自动登记
  → 管理员创建项目、分配角色
  → 成员在Collaboration菜单选择项目
  → 资料 → 分析 → 方案 → 逐角色确认 → 任务与成果 → 接收
```

钉钉在本MVP中只承担身份认证，不是另一个项目业务入口，不做群机器人或消息通信。

## 2. 必须实现的最少功能

### 2.1 单一服务入口

- 服务器继续作为DSH插件运行，复用现有宿主Agent／模型和业务能力，不另建第二套运行时。
- 一个可信HTTPS入口承载登录、业务会话和既有附件传输；内部复用现有通信及业务能力，只替换依赖个人SSH的接入部分。
- 客户端只输入服务地址，不输入成员账号／UserID／私钥路径，不导入个人JSON或手改hosts。
- 不按个人固定IP授权。所有已有网络路径可到达入口的LAN／ZeroTier用户都能发起登录，服务端再验证组织身份。
- DNS、证书和监听由管理员一次部署；部署前从A／B实际路径验证，不用“能连SSH”冒充浏览器登录入口已可达，不忽略TLS校验。
- 不顺带开放公网业务、服务器shell或整个DSH管理接口；互不路由的物理网络不会自动变得可达。

### 2.2 电脑钉钉登录

- 限当前指定钉钉组织的有效内部人员；官方端内免登确认身份，再由服务登记或复用稳定成员身份。不读取钉钉本地登录文件，不接受自报名义。
- 登录请求一次性、限时并绑定原DSH发起者；不能由另一设备抢领、重放授权码或把授权结果塞进可分享配置。
- 优先使用官方电脑钉钉应用页；DSH提供打开入口，端内显示组织／身份／服务并由本人确认，DSH自动取得结果，无“我已扫码”按钮。
- 自动唤起若需要额外专用适配，不作为首版闭环阻碍；使用已获用户同意的PC钉钉工作台进入同一应用作为可靠入口，保留本次请求的安全绑定。不是手机扫码兜底，不要求输入账号或手工抄授权码。
- 电脑钉钉未安装、未登录、组织不匹配、授权超时等明确报错，不悄悄回退共享账号或旧SSH身份。
- 保留前轮已确认的7天设备登录记忆、多设备各自登录、本机退出与重新登录；不新增设备管理台。7天是最长有效期，不因使用而静默变永久。
- 7天记忆不等于7天不核对组织资格。复用已有最多5分钟的组织有效性缓存；到期无法复核时明确暂停业务，官方明确否认资格则旧登录不可继续。这个服务端认证保护不是成员管理功能，不建设停用／恢复管理流程。
- 登录秘密不进入可分享JSON、URL、浏览器业务状态或日志；使用宿主可用的本机安全存储，缺少能力时先解决／报告，不改为明文保存或静默取消7天要求。

### 2.3 最小管理员功能

- 初始且固定管理员：陈锦鸿，按现有组织作用域中的稳定官方身份核验后配置，不按昵称或“第一个登录的人”判断。
- 在DSH“设置→协作服务”中，管理员比普通成员仅多两个必要入口：**创建项目、项目角色分配**。
- 只有管理员可以创建项目、分配／调整角色；普通成员和业务模型不能绕过服务端检查创建项目或自取职责。
- 项目角色分配的下拉列表只读展示已经自行登录、自动登记的成员，这是分配职责需要的查询，不是成员管理台。
- 新成员尚未出现时先自行登录，管理员刷新列表后再选择；不手工录入身份或上传公钥。
- 沿用九类职责、一角色一成员（允许空缺）、一人可兼多角且分别作决定。角色修改需明确提交并核对当前版本，不自动替人作业务决定。
- 新增／停用／恢复／删除成员、增加／撤销管理员、设备列表和远程批量撤销、邀请审批都不做。
- 项目归档／删除管理不作为此次必做新增功能；不为本MVP搭一个全面项目后台。

### 2.4 项目业务保留最小既有规则

- 所有有效成员看到全部项目目录与项目共享内容；取消逐项目参与名单，不新增授权／申请／审批机制。
- 非管理员也可以开展普通资料／分析／方案协作；正式方案确认、任务完成、成果接收由该职责当前成员本人进行。
- 角色空缺阻断相应正式决定。角色换人或官方资格失效时，相关未生效方案暂停，明确修订后由全部相关职责成员重新确认；旧确认不改挂、已生效事实不自动回滚。
- 在现有Collaboration菜单选项目，新会话明确选择，已建立对话固定原项目；同一人多角色仍分别决定。
- 私人对话不因全员项目可见而共享；成员／项目会话和附件引用归属仍隔离，不把项目业务记录与个人未提交聊天混为一谈。
- 断网只恢复已保存记录；不自动重发旧指令，结果不明先查实际状态。
- 复用已有附件和业务状态机，不为认证改造顺带重写整套业务功能。

## 3. 明确不做

| 不进MVP | 理由 |
|---|---|
| 成员管理台及其增删改、停用／恢复、邀请、审批 | 普通人员首次官方登录自动登记即可 |
| 动态管理员／管理员交接／最后管理员保护页面 | 单个指定管理员是部署配置，无动态管理员操作 |
| 逐项目访问名单或权限配置 | 当前全员项目共享可见 |
| 钉钉机器人、群聊、IM问答、通知订阅、自动消息投递 | 当前只验证钉钉身份＋DSH业务 |
| 手机扫码、多组织／外部联系人接入、其他身份提供方 | 单组织电脑端闭环即可 |
| 自动发现服务器、跨网络自动组网、每人SSH或hosts脚本 | 成员只用一个已配置可达的地址 |
| 全新独立业务运行时／全面管理网站／平台级IAM | 保持两个插件和现有DSH宿主 |
| 新的自动任务推进、后台模型分析、自动补发业务 | 与接入和角色分配无关 |
| 旧业务迁移、备份及兼容旧SSH认证继续业务 | 用户明确全新开始且不备份 |

## 4. 仅实现必要的服务端保护

少做管理功能不等于不鉴权。以下不是独立功能模块，而是闭环正确性所必需：官方组织／用户身份校验、一次性登录请求绑定、TLS、有限登录有效期、身份与对话归属、管理员写操作验证、职责本人决定、参数／附件限额、基本登录限流、不记录凭据、旧实例凭据失效。

不建设可配置的权限平台；用最少规则固定本MVP的两个身份类别：**指定管理员、普通组织成员**，再叠加现有项目职责本人规则。

## 5. 无备份重建边界

最终批准后先核对实际绝对路径、系统用户和会话归属。只删除本套协作的旧成员绑定／角色／登录、项目业务与附件、协作专属远端会话／通信队列、旧个人dt_系统账号及授权、A／B插件旧配置和映射。

保留Ubuntu管理员admin0、系统与ZeroTier、钉钉组织应用及服务端凭据、HTTPS证书、CPA服务和模型配置、程序源码、其他DSH普通会话与个人原始文件。不复制或备份旧协作数据，不创建数据快照；归属不明确的对象先停下查明，不泛删整个.dsh、用户目录或共享会话数据库。

A／B旧客户端状态只清理本插件拥有的部分；B本机由B执行已核验的清理／配置步骤，不能假称服务器操作已替B完成。本机不再保留旧插件账号自动回退入口。

## 6. 实施顺序与完成门槛

1. 用户确认本精简方案后，先验证官方PC钉钉端内登录、真实版本／应用发布／PC首页，以及可用的HTTPS／DNS／安全存储路径；不为验证读取或复制旧业务库。
2. 修改两个插件，围绕最小闭环测试；先本地／隔离测试，再GitHub双平台CI成功的固定版本。必要新测试验证真实宿主接入边界，不只验证假RPC对象。
3. 隔离环境通过真实电脑钉钉最小登录后，核对清理范围，在无正在执行的业务写入时维护停服；不强杀业务、不先清库再发现官方登录不可用。
4. 按已确认边界无备份清理、部署新服务和新客户端配置，退役旧成员SSH通道；只操作本套协作，不启用机器人、不改CPA路线。
5. 由A／B本人完成下面的真实验收；助手不代替登录确认。切换失败停止新业务并报告，不退回旧SSH身份、不声称能恢复已删除数据。

| 最小验收 | 必须观察到的结果 |
|---|---|
| A／B接入 | 各自从实际LAN／ZeroTier路径用一个HTTPS地址正常连接，成员不用公钥包或hosts脚本 |
| 首次电脑钉钉登录 | 两个不同人使用PC钉钉完成身份确认，原DSH自动获得各自身份；无手机扫码／自报UserID／抢领 |
| 自动登记与持久登录 | B首次登录后在角色选择器出现；重启DSH身份记忆可用，同人复用身份、换人不继承私人对话 |
| 管理员创建／分配 | 陈锦鸿创建一个全新演练项目，将两个职责分别分给A／B；普通成员界面和直接请求都不能建项目或改角色 |
| 全员可见 | B无需逐项目授权即能从菜单看到新项目并选择 |
| 最小业务链 | 一份小文本资料→一次分析→最小方案→A／B分别确认→最少任务和成果→接收，身份追溯正确 |
| 职责／隔离边界 | 代替另一角色确认被拒；空缺不通过；角色换人不继承旧确认；私人对话、项目会话不串用 |
| 失败与退出 | 网络失败不伪报登录／提交成功、不自动重发；本机退出后旧设备资格不能继续访问 |

7天边界、授权码重放、组织资格失效、错误服务／设备领取、未认证管理操作等用可控时钟／合成身份测试覆盖；不能假称已等待7天真实验证。真实业务模型验收仅按本轮明确试跑范围执行，不自动批量调用。

## 7. 最终确认

前三轮已确定产品规则，本版只收缩范围，不新增成员管理要求。用户已回复“确认，开始实施”，批准先进行非破坏性的实现／最小可行性验证；破坏性重建仍按第5／6节的先核验清单、先真实登录可行、后停旧清理顺序执行，不将最终批准误用为跳过前置验收。

若技术核验发现“一个地址／电脑端确认／7天安全记忆”等必须目标无法成立，报告具体事实和最小替代选择，不擅自改回扫码、公钥包、明文秘密或扩大公网访问。
