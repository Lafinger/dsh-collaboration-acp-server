# 0.7.2-rc.12：组织联系人类型严格校验

在[rc.11组织资格与姓名主动同步](<RELEASE-0.7.2-rc.11.md>)基础上修复最终只读审查确认的问题：将`contact_type`强制转为字符串会把畸形数组`[1]`误判为明确外部联系人，进而撤销已有设备；`[0]`也会被错误接受为内部成员。

现在仅接受官方数字／字符串枚举：`0`／`"0"`表示内部，`1`／`"1"`表示外部。数组、对象、布尔值、null、缺项及其他枚举一律暂不可核验，不视为明确离职、不续旧核验期限，不允许新分配。响应`errcode`成功值同样只接受明确数字／字符串零或现代接口省略该字段，不把`[0]`等可转换值当成功。原有效枚举、端点精确错误码、active=false激活语义保持不变。

新增联系人类型／成功错误码合成响应矩阵和真实内存SQLite回归，验证畸形类型只标记unknown，旧设备在原有效租约内保持有效，成员revision、职责冻结与撤权审计不被误修改。

无数据结构／协议变化，继续使用配套客户端0.6.3-rc.9，客户端由用户自行安装。rc.11公开标签和资产保持原样；本版使用新的受保护PR、main、tag与发行流程。当前文件仅记录变更范围，不能替代CI、公开产物核对或生产部署证明；未调用真实钉钉、模型或业务。
