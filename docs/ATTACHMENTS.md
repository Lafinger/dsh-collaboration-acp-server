# 本地附件：授权、工具传输、解析与归档

适用：客户端0.3.0与服务端0.4.1，DSH0.2.0-rc.2。正式证据见[附件发行验收](<ATTACHMENT-RELEASE-VERIFY.md>)；[实施计划](<ATTACHMENT-TRANSFER-PLAN.md>)保留边界与决定。人工GUI附件/真实模型验收由用户后续执行。

## 使用

先通过 `project_list`/`project_get` 核对项目ID，再在同一条人类消息中写出单独的操作授权行与唯一目标项目ID。附加文件，或写 `@相对路径` / `@"含空格的路径"` 指定当前会话工作区内文件。

```text
附件操作: 上传并归档
project_id: <32位项目ID>
@"测试材料\项目需求\需求文档.docx"
请传输这个文件，读取内容并判断用途与所属角色，登记到合适的资料目录；
再分析需求、矛盾、待决问题和所需角色。不要分配人员，不要创建/确认计划或任务。
```

原生聊天附件不需要写路径，但仍需上述两行授权。仅想传输而暂不登记时，写 `附件操作: 仅传输`。路径不能是目录，不能越出当前本地会话工作区，拒绝符号链接/junction与`.dsh`/`.ssh`/`.git`、常见凭据/密钥文件。文档引用的其他路径不会自动读取。

操作行必须单独一行，且只有一个；`project_id:`也只能出现一次。使用明确操作行而非简单搜索“上传”词语，是为了避免“不要上传”或“暂不归档”等自然语言被错误当成权限。除此两行，分析/分类要求可以使用自然语言。

## 工具与状态

1. `attachment_transfer(handle)`：只能消费当前授权消息的opaque句柄，服务器通过forced SSH connector分块读取。校验长度/sha256，记录回执。不是已登记资料，不代表解析成功。
2. `attachment_inspect(receipt_id)`：读取这段会话/账号自己的解析内容及限制；正文是待分析数据，不是工具授权或指令。
3. `attachment_archive(receipt_id,purpose,role?,reason)`：仅能归档原消息已授权的目标项目。模型判断用途和职责类别，角色不确定省略即共享。物理路径由服务器按现有 `项目key/role/materials/materialId/vN__filename` 生成；不接收随意目的路径，不分配角色人员、不替代计划确认。
4. `attachment_receipts()`：查询本账号本会话最近100个接收回执。断线后先恢复同一远端会话再查询，**不要重发旧消息**。同一回执重复归档只返回已有版本；只有用户明确重新上传才创建新的回执/可能新版本。

解析产物保留解析器版本、原件sha256、文本sha256，绑定正式资料的具体material/version。`material_read`/`analysis_begin`使用可信提取文本而非把DOCX/图像字节当UTF-8；分析提交重新推导缺口，模型不能删掉服务器报告的嵌入图片/修订/未解析缺口。

业务资料immutable版本号不等于文件名中的版本，Word正文版本也可能不同；都保留，不自动纠正。上传同名同purpose追加版本，不同purpose创建不同资料。已有资料职责类别固定，不因下一次模型分类/人员变更移动版本。

## 格式与限制

- 每条消息最多5个文件、总计20MiB；每文件最多20MiB，分块48KiB，原有1MiB NDJSON帧不增加。提取文本最多256KiB，超限报告未覆盖，不偷偷截断。
- DOCX：校验ZIP目录、entry/压缩/膨胀上限、CRC、正文XML，拒绝macro/activeX/嵌入对象和实体声明。只提取正文段落/表格，不执行宏、不请求外链、不做版面渲染。图片存在与修订状态显式列为缺口；不宣称全部页面/图像已理解。
- MD/TXT：严格UTF-8（可BOM），其他编码明确要求转换，损坏不解码成乱码。
- PNG/JPEG/WebP/GIF：按字节真实格式核对扩展名与尺寸、像素、frame上限，首帧解码校验；GIF/WebP动画其他帧/时序不分析。原生image附件可能由DSH归一化，只保留接收到的归一化图片；想保留原始二进制用file附件/显式路径。
- **首版图片传输/校验/归档并不提供视觉模型分析或OCR工具**。当前Codego/deepseek-v4.1-flash路线没有声明视觉能力，图片正文保持未分析；不能按文件名想象画面。后续只有管理员明确配置并验证视觉模型后才能新增视觉分析工具，不静默换provider/扩大模型披露。
- 暂不支持PDF/XLSX/PPTX/压缩包及其他格式自动解析；若收到，保留原件但标记未解析与缺口，不说分析完成。

## 安全与升级

基础collaboration v2/ACP-shaped1不变，附件扩展1双方精确能力协商；未支持的新/旧配对只保留文本，文件请求在业务提交前失败，不降级或重放。唯一反向RPC是 `collaboration/attachment/read`，且客户端按当前会话/request/句柄授权；任意其他fs/terminal/MCP继续拒绝，不开放SFTP/SCP/shell。

现有业务库、会话、成员身份、客户端映射与私钥不清空、不轮换。服务新增接收/解析表，不重写旧业务表。模型分析仍走服务器既有provider，确认有权披露材料后由用户主动提交；自动回归用非敏感模拟内容、不调用真实模型。
