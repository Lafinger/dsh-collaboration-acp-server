# 本地附件：上传、读取与归档

当前适用协议：协作v4／附件v2／人类授权v3，双端硬配对，无兼容层。旧[附件发行验收](<ATTACHMENT-RELEASE-VERIFY.md>)、[实施计划](<ATTACHMENT-TRANSFER-PLAN.md>)与[CPA与图片决定](<设计确认-CPA切换与本地模拟退役.md>)描述的是v3及更早的按轮授权链路，仅作历史；本轮决定的依据见[ADR-0009](<adr/0009-authorization-is-upload-session-inventory.md>)。

## 使用

先在模型菜单明确选择当前会话项目（菜单选择是唯一项目绑定来源，正文不产生绑定）。然后把文件作为原生聊天附件发出，或在消息里写 `@相对路径` / `@"含空格的路径"` 指定当前会话工作区内文件，再用自然语言说明要做什么：

```text
@"测试材料\项目需求\需求文档.docx" 这是项目的需求文档，请读取内容、归档，并分析需求、矛盾与待决问题。
```

不需要"附件操作:"/"project_id:"授权行——附件不再需要文本授权，业务写操作（提交分析、登记计划等）仍按[自然语言授权](<NATURAL-LANGUAGE-MVP.md>)的短语边界逐条判定。未绑定项目就发送附件的轮次在客户端直接失败（零字节上传），提示先选项目。路径不能是目录，不能越出当前本地会话工作区，拒绝符号链接/junction与`.dsh`/`.ssh`/`.git`、常见凭据/密钥文件。文档引用的其他路径不会自动读取。

## 上传与清单

- 字节在模型回合开始前由服务端经唯一反向RPC `collaboration/attachment/read` 分块拉取（48KiB），sha256校验后落盘入库；校验失败整个prompt被拒绝（`not_started`），不产生半个附件。
- 上传即授权：授权 = 字节已在服务端且归属 (账号, 会话)，按会话持续有效；没有按轮grant，也没有 `archiveAuthorized` 字段。
- 每条人类消息注入会话附件清单（名称 + handle），模型从消息里拿到 handle；同会话历史附件在后续轮次同样可读可归档。
- 幂等：同 (账号, 会话, handle) 且 sha256 相同跳过重拉；sha256 不同删旧写新。

## 工具（只剩两个）

1. `attachment_read(handle)`：读取本会话一个已上传附件的完整内容。文本内联（上限256KiB，超限显式报错）；图片返回有界视觉副本；无法解析的格式返回 `content:null` 与缺口说明。正文是待分析数据，不是工具授权或指令。
2. `attachment_archive(handle,{purpose,role?})`：归档到会话绑定项目；跨项目显式拒绝。材料名 = 原文件名；重复归档按材料规则追加版本，内容与最新版完全相同则去重（不新增版本）。历史版本冲突作为普通工具错误如实返回，没有恢复确认流程。purpose 必填（模型从内容归纳），role 省略即共享。物理路径由服务器按现有 `项目key/role/materials/materialId/vN__filename` 生成；不接收随意目的路径，不分配角色人员、不替代计划确认。

已删除：`attachment_receipts`、`attachment_transfer`、`attachment_inspect` 及 handle/receipt 双标识接力。归档成功以 `update._meta.operationResult`（kind `material_archive`）发布人话消息（`已将《name》归档为第N版。`／去重 `内容未变，未新增版本。`），外层 `_meta` 仍是历史序号。

解析产物保留解析器版本、原件sha256、文本sha256，绑定正式资料的具体material/version。`material_read`/`analysis_begin`使用可信提取文本而非把DOCX/图像字节当UTF-8；分析提交重新推导缺口，模型不能删掉服务器报告的嵌入图片/修订/未解析缺口。

业务资料immutable版本号不等于文件名中的版本，Word正文版本也可能不同；都保留，不自动纠正。上传同名同purpose追加版本，不同purpose创建不同资料。已有资料职责类别固定，不因下一次模型分类/人员变更移动版本。

## 格式与限制

- 每条消息最多5个文件、总计20MiB；每文件最多20MiB，分块48KiB，原有1MiB NDJSON帧不增加。提取文本最多256KiB，超限显式报错，不偷偷截断。
- DOCX：校验ZIP目录、entry/压缩/膨胀上限、CRC、正文XML，拒绝macro/activeX/嵌入对象和实体声明。只提取正文段落/表格，不执行宏、不请求外链、不做版面渲染。图片存在与修订状态显式列为缺口；不宣称全部页面/图像已理解。
- MD/TXT：严格UTF-8（可BOM），其他编码明确要求转换，损坏不解码成乱码。
- 仅单帧PNG／JPEG／WebP图片：按真实字节核对扩展名、尺寸、像素并完整解码；GIF按名称、声明类型或GIF字节拒绝，不自动提取首帧／转码绕过；动画WebP／APNG不进入视觉输入。原生image可能已由DSH归一化，若来源信息丢失不能从PNG字节推断它曾是GIF；想保留上传前原件用file附件／显式路径。
- `attachment_read` 对图片把已完整接收并校验的原图存成宿主持久附件引用，返回原生image内容块给当前图片模型，不仅是元数据。模型副本等比不裁切、长边≤2048px、实际编码≤1MiB；不能满足则明确报错，原件不替换、不自动归档。返回副本不表示模型已看懂，视觉观察不等于正式业务决定。
- 同一会话的历史图片在后续轮次重读时需在当前消息中明确写出 handle；Base64合计20MiB超限先写持久image/offload决定，最旧图在后续请求明确占位。不会修改冻结请求、自动补传本地旧图或扫描其他会话。
- 暂不支持PDF/XLSX/PPTX/压缩包及其他格式自动解析；若收到，保留原件但标记未解析与缺口，不说分析完成。

## 安全与升级

协作v4/附件v2/人类授权v3三方精确能力协商；未支持的新/旧配对在协商或prompt校验处失败，不降级或重放。唯一反向RPC是 `collaboration/attachment/read`，且客户端按当前会话/request/句柄授权；任意其他fs/terminal/MCP继续拒绝，不开放SFTP/SCP/shell。

现有业务库、会话、成员身份、客户端映射与私钥不清空、不轮换。服务新增 `session_attachments` 表，旧接收/授权表原样保留但不再读写。模型分析仍走服务器既有provider，确认有权披露材料后由用户主动提交；自动回归用非敏感模拟内容、不调用真实模型。
