# 设计讨论：通用文本读取与关联说明

日期：2026-11-02。状态：Q1–Q9 已确认；用户已最终确认共同理解并批准本地实现与离线测试。本地实现已完成，验证结果见文末；未提交、发布或部署。

## 背景与依据

- 设计时参考工作台私有交接（不随独立仓库分发）；其发布基线为服务端 rc.8、客户端 rc.7，协作4／附件2／人类授权3。可公开核查的服务端基线见 [rc.8 发行说明](<RELEASE-0.7.2-rc.8.md>)，客户端见 [rc.7 Release](<https://github.com/Lafinger/dsh-collaboration-client/releases/tag/v0.6.3-rc.7>)。
- 用户明确的新目标：只要文件以文本形式存储就可阅读；不支持读取的二进制文件可另读其关联说明。参考用户提供的“协作服务”会话：HTML 原件上传归档成功，但读取返回格式不支持。
- 当前实现事实：附件解析只将 TXT/MD 当普通文本，其他格式按 DOCX/图片专用分支处理；HTML 等被存为 unparsed。历史附件和资料提取缓存不按解析器版本刷新。材料无缓存后备路径却对非 DOCX/图片尝试 UTF-8，存在读取通路不一致。源码见 [attachment-parser](<../src/attachment-parser.mjs>)、[attachment-service](<../src/attachment-service.mjs>)、[material-service](<../business/src/service/material-service.ts>)、[analysis-service](<../business/src/service/analysis-service.ts>)。
- 当前没有独立的文件到说明材料版本关联：资料 purpose 是自由文本，成果版本有 summary/self_check/files 共同记录；下载原件不等于读取原件。

## 第一轮：已确认（用户答复“都按建议来”）

### Q1 文本原文读取

不按 MD/TXT 后缀限制普通文本。HTML/CSS/JavaScript/JSON/XML/日志/无后缀文本可按内容识别后读取原文。HTML 不去标签、不渲染，不执行脚本或加载外链；文件内容不是人类操作授权。静态读取不证明浏览器运行或验收通过。编码与大小界限待后续确认。

### Q2 保留既有专用读取

“不读二进制”指不将任意二进制字节硬解码为普通文本；保留现有 DOCX 正文提取、图片视觉读取能力。本轮不新增其他二进制格式解析。现有 GIF 禁传等边界不因扩展普通文本而自动改变。

### Q3 关联必须明确

说明关系由用户在请求中明确指定，或使用系统已有的明确关联；不靠同名、同目录、正文中的其他路径自动绑定或扫描本地文件。分别说明原件可读性、实际读取的说明、仅由说明支持而未核实原件的结论。关联粒度与是否持久化尚待确认。读取说明不自动消除原件未读缺口。

## 第二轮：已确认（Q5用户修改，其余按建议）

### Q4 编码与文本判定

支持严格 UTF-8（含 BOM）、带 BOM 的 UTF-16 LE/BE。解码后拒绝 NUL 与非文本控制字符，保留制表符、换行等正常文本字符。后缀、MIME、HTML charset 不作为普通文本可读性的决定依据，不自动猜 GBK 或无 BOM UTF-16。无法可靠解码时明确报告不属于受支持编码的文本或为二进制，并提示转存 UTF-8。既有 DOCX/图片保留专用通路。

### Q5 取消正文读取大小上限

用户明确答复：“Q5 读取大小取消上限限制。其他都按建议来。”

不采用保留 256KiB 的建议；取消附件读取、资料读取和分析读取的正文大小上限，不按文件大小将文本判为不可读。不得静默截断。原件上传限额是否保持、模型上下文等外部限制怎样表述，待下一轮确认。

### Q6 历史缓存读时刷新

实际读取时根据解析器版本从保存的原件重新解析并核实原件哈希，覆盖附件及归档资料，不要求重传，不批量扫描全库。只刷新可再生成的解析缓存，不改原件、不新增资料版本、不重写历史分析或正式决定。缺失或损坏仍明确报错，说明不能替代原件读取。

### Q7 关联说明最小闭环

本轮不新增关联表或自动找说明工具。用户在消息中显式配对已上传文件；归档资料使用明确的资料 ID 与版本；成果沿用固定版本的摘要、自检与附件清单。找不到指定说明就报缺失，不按名称猜、不扫描目录。正式分析的原件与说明都显式列入 scope，不自动扩大范围；原件未读缺口保留，并区分说明所述与原件已核实内容。

## 第三轮：已确认（用户答复“都按建议来”）

### Q8 保留上传与格式安全边界

单文件原件 20MiB、每条消息最多 5 个附件保持；取消的是正文读取限额，包含 DOCX 提取正文的 256KiB 限额。格式完整性校验、图片尺寸等既有边界保持，不扩大原件上传能力。

### Q9 完整返回与外部限制

服务端默认完整返回正文，不新增分页、分块、自动摘要、软限额或静默裁剪。可观测的传输、模型上下文或资源错误如实报告，不能声称全文已读。服务返回完整正文、模型逐项检查全文、实际运行或验收是三个不同事实；不承诺无限资源或无限模型上下文。

## 验收标准（由已确认决定推导）

1. HTML、CSS、JavaScript、JSON、XML、日志、无后缀文本按原文读取；源码不被执行、不加载外链。
2. UTF-8（含 BOM）和带 BOM UTF-16 LE/BE 读出正确正文；非法编码、NUL/非文本控制字符不冒充普通文本；不以改成 TXT 后缀绕过判定。正常制表符、换行保留。
3. 超过 256KiB 的普通文本及 DOCX 提取正文，在附件读取、资料读取、分析读取中均不因正文大小拒绝；对返回全文做长度与末尾内容核对，确保未静默截断。
4. 旧版已保存为 unparsed 的 HTML 在读取时重新解析；已归档、归档去重和无提取缓存的资料读取路径结果一致，不要求重传、不新增资料版本。当前版本缓存可复用。
5. 重解析保留原件字节/哈希、资料身份与版本、历史分析及决定；原件缺失或哈希不符时不能伪造成功。
6. 二进制原件不可读时，用户指定的可读说明能单独读取；未指定、缺失说明或分析 scope 未列出说明时不自动扫描或跟读；仍保留原件未读缺口。
7. 既有 DOCX/图片能力、GIF禁传、上传限额、权限与本人决定门禁、原件下载不回归；不把离线测试冒充真人/模型验收。
