# dsh-im 钉钉接入与统一成员认证方案

**状态：已完成架构审查与取舍确认，待实施。** 本文只写架构、关键规则和验收，不含代码或接口细节。审查发现及依据见[审查记录](<DSH-IM-DINGTALK-REVIEW.md>)。本次不安装、不改实现或部署、不发布、不清库；设计修复不代表现有系统已具备相应保护。

> 后续实施说明：上述状态记录的是本文件架构审查时点。用户随后批准实施，当前代码及验证进度单独见[实施记录](<DINGTALK-IMPLEMENTATION.md>)；历史设计依据不替代真实平台验收。

## 1. 目标与范围

服务器集中钉钉机器人负责沟通、提醒和受控查询；成员在 DSH 扫码登录和在钉钉提问时映射为同一协作成员，不共享私人上下文。

- 首期单钉钉组织、集中应用机器人；由明确指定的协作管理员开通成员及项目参与资格，不自动注册、授予角色或开放项目。
- 项目机器人代表协作服务，不占 pm／product 等九个职责角色，不是所有人的共同业务身份。转达消息标明实际发起人，系统提醒不冒充成员。
- 项目群承载允许公开的项目摘要和澄清沟通；机器人私聊承载本人待办、个人提醒与私人查询。群发问不意味着个人查询结果可在群里公开。
- 支持显式文本请求／关联答复、订阅提醒、资料目录和状态等有限查询。正式项目修改、归档、分析提交、方案确认及成果操作仍在 DSH；钉钉的“同意”仅是通信文本。
- 首期不开放钉钉文件传输、资料全文、任意搜索、全群监听归档、跨项目连续上下文或 Agent 自动推进。

## 2. 架构与职责

```text
成员 DSH 客户端                          钉钉项目群／机器人私聊
    │ 登录入口 → 可信 HTTPS 登录页                │ Stream／平台消息发送
    │ 本服务登录凭据＋受限 SSH                    ▼
    ▼                                      dsh-im 钉钉适配器
┌────────────────── 同一服务器 DSH Host ────────────────────┐
│ 身份／登录服务 ←→ 统一项目访问控制 ←→ 通信桥接层 ←→ dsh-im │
│                         │             持久接收／投递状态  │
│                  受限协作业务入口                         │
│      按成员、项目、渠道与可见范围隔离的会话／工具           │
└─────────────────────────┬────────────────────────────────┘
                          ▼
        业务权威记录／原件／会话＋通信记录／授权与管理审计
```

| 组件 | 职责与边界 |
|---|---|
| 协作客户端 | 登录／退出／到期状态；绑定当前成员的安全连接与项目会话；查询通信记录；不自行声明业务身份 |
| 身份与登录服务 | 验证钉钉授权、组织及稳定用户标识，管理成员绑定、设备登录、全局停用；平台长期秘密留在服务器 |
| 统一项目访问控制 | 两端共用，检查当前成员资格、对象真实项目和操作范围；不由提示词或模型决定 |
| 通信桥接层 | 受控接收、请求关联、可见范围、订阅、持久消息和投递状态；不自动产生正式业务决定 |
| dsh-im | 平台连接、机器人凭据、消息收发与展示；不是成员权限、项目事实或唯一消息历史的权威 |
| 原协作服务 | 继续保存资料、分析、方案、任务和成果，保留逐角色确认规则；新增访问校验不能绕过它们 |

**同 Host 是目标，不是安装保证。** 当前精简 profile 缺少 dsh-im 所需的 connection、Typert gateway 和会话／工作区管理服务。先在隔离环境验证补齐依赖及生命周期，不另建第二套业务运行时；管理接口只供本机或受控管理员使用，不向机器人用户或公网开放整个 DSH。

该机器人必须只走专属受控链路：禁用默认普通宿主会话、会话切换／模型切换、远程审批和私人会话双向同步；不得为同一入站消息启动两个消费者。其工具与模型配置不随其他宿主会话变动。

## 3. 身份认证与登录生命周期

**用户扫码登录与机器人绑定是两条不同链路。** 采用钉钉新版网页登录授权，不使用已迁入历史的 SNS 扫码流程。

- DSH 提供登录按钮，打开服务器控制的 HTTPS 登录页；二维码页与授权回调遵守官方同源要求。原客户端安全领取本次登录结果，授权结果不能被另一客户端、服务或连接重用；不把长期令牌放进跳转地址。
- 服务器交换授权结果，确认指定组织和当前用户；以受信任的组织／应用作用域完成登录用户标识与机器人 senderStaffId 的对应。不能直接把 unionId、senderId、userId 当同一个值，也不采用昵称或手机号猜测绑定。
- 使用企业内部应用及必要成员信息权限；身份转换、组织内员工判断和私聊发送人识别均是验收门槛。缺失可信字段、作用域不一致、未开通或身份转换失败即拒绝，不照用 dsh-im 默认 senderId 回退。
- 本服务签发有范围的设备登录资格并由服务端验证；客户端以扫码替代手填业务身份，但仍需要可信服务地址、SSH 密钥和主机校验。SSH 是安全通道，不单独授予业务访问；扫码成员必须匹配管理员配置的 SSH 入口。
- 当前设备登录最长 **12 小时**，到期重新扫码；平台 token 到期不等于本服务登录到期，不以刷新平台 token 获得永久登录。
- 设备退出／到期只停止该设备的服务访问，不停用成员在钉钉的入口；管理员停用、解绑或撤销资格阻断两端。钉钉每次访问核对成员及项目资格，不依赖 DSH 是否在线。
- 组织资格复核须有明确的有限有效期；部署前配置并验证复核窗口，过期或复核失败时拒绝新业务请求，不无限沿用缓存。长连接、恢复历史、每次工具操作和投递前均检查最新本服务授权。
- 撤销阻止后续授权操作、中止仍在处理的请求并停用相关上下文；写入／投递前再次校验，防止检查与执行之间的资格变化。已提交事实不回滚；已出站到平台的消息不承诺撤回。

## 4. 项目资格、管理与上下文

这是**新增权限模型**，不是原 MVP 已有能力。项目参与资格、职责角色、管理资格三者分开。

- 协作管理员明确管理项目参与名单、角色安排、目标与订阅，管理操作留痕；管理员不因管理资格自动读取成员私人历史。普通成员不能自行换角色取得确认资格。
- DSH／钉钉统一校验项目列表、查询、正式写入及所有关联对象。必须解析资料、分析、方案、任务、成果的真实归属；不能只检查外层 project_id、只隐藏菜单或只保护机器人入口。首期不支持跨项目资料引用，恶意关联 ID 与未授权对象在进入模型前被拒绝。
- 新项目的初始参与名单由管理员明确建立，不默认所有组织成员可访问。项目资格撤销同时阻断该成员的旧角色操作与订阅，角色仍可保留为历史事实，不能继续授权。
- “本人待办”由可信成员解析其当前角色并过滤，调用参数不能扩大身份或角色；角色待办已读不作个人收悉回执。
- 相关角色换人，或其确认成员失去全局／项目资格时，**尚未生效的受影响方案暂停生效**。旧确认（含拒绝）保留为历史；由人明确修订新版本，再收集全部相关角色确认，不自动修订、抹掉拒绝或替新人同意。已生效方案及已完成成果决定不自动回滚。
- 会话固定项目范围，并隔离 DSH／钉钉、群公开查询／成员私聊。切换项目使用独立上下文，跨项目只返回权限过滤后的目录，不拼接私人历史；权限撤销后不能靠旧模型上下文继续回答。
- 登出、换人及重连隔离登录、会话映射与缓存。已呈现到成员本机或已发送到平台的内容不能保证收回；管理员撤销控制未来访问，不等于删除对方已有副本。

## 5. 沟通闭环与群可见范围

**闭环**：Alice 显式发起项目澄清请求 → 校验参与资格、受众与目标 → 保存请求及发送意图 → 投递 → Bob 的可信答复关联原请求 → 持久记录 → Alice 查询或按订阅获得提醒。

- 项目群只输出明确允许向该群公开的摘要和公共澄清记录，不以“用户问了”自动公开任何记录。个人请求不可自动转成公共澄清；私人信息统一提示到机器人私聊。
- 仅在可验证全体群成员范围的群中投递受保护内容，群成员必须满足项目资格。所选群须真实具备适用的群模板／群聊酷应用能力及权限；不是任意普通群都可查询成员。校验缺失、过期或失败即暂停受保护群投递，只允许无敏感信息的引导。
- 发问者资格与回答受众分别校验。群成员变化、项目成员变化、机器人更换或目标改址均使原受众校验失效；发送前重核，不自动改投私聊、另一群或其他人。平台群成员变化存在外部竞态，不能宣称与本库权限变更原子同步。
- 只保存明确发给机器人的通信和可确认关联的回复，不承诺看到群全部消息。请求使用稳定关联标识；平台原生引用不足或关系不确定时要求显式关联，不能靠模型猜测。
- 澄清记录不是分析未决事项的处理状态，也不自动成为正式需求或任务。成为正式资料／结论需回 DSH 明确归档或发起业务操作；不覆盖原不可变分析。
- 业务提醒从已提交事实派生并按启用订阅发送，保留持久投递意图；发送前重核资格、当前版本及是否仍需处理，过期提醒不作为当前指令。多角色提醒可汇总，正式确认仍逐角色。
- 不自动广播全部变更、不后台分析／派活；固定模板通知不调用模型。成员主动问答才按既有模型路线使用模型，受控输出不展示思考过程或未审核的模型流片段。

## 6. dsh-im 能力与可靠性门槛

基线：**dsh-im v4.39.0／DSH 0.2.0-rc.2**。已核对公开源码，尚未验证本项目组合或真实钉钉授权。

| 当前已有 | 仍须补齐／验证 |
|---|---|
| 钉钉 Stream、私聊／群聊主动发送、卡片展示 | 钉钉独占受控文本接收、可信身份与目标校验、原消息关联 |
| 同 Host 投递服务 | 当前精简宿主依赖补齐与管理能力隔离；不能复用无鉴权 HTTP 作认证或公网投递 |
| 默认机器人入站处理 | 默认链路先 ACK 再异步处理，不能证明已持久保存；可靠接收要另设契约并验证 |
| 稳定机器人和目标别名 | 目标可修改、机器人可替换；须固定并重核实际路由，别名本身不是权限证明 |

- **先校验并可靠登记，再向平台确认接收**；拒绝与重复消息也须有可核对的处理结果。以机器人／组织／消息标识防重复，保存后异步处理，不等待模型完成才 ACK。ACK 与保存顺序无法保证时报告缺口，不能宣称可靠双向上线。
- 不承诺平台断线期间完整历史补投；普通接入不能假称存在恢复游标。断线／处理失败提供明确状态与人工核对入口，不能用定时扫全群或重新发起旧业务补洞。
- 发送意图先持久保存，区分待发、平台接受、明确拒绝、部分发送、结果未知。进程恢复不把在途状态自动改为未发送；结果未知不盲重发，未出站且已证实安全的发送才可按受控策略继续。
- 超长消息的多段发送逐段关联并保留状态；部分成功后不重发整条。平台回执不可得时不伪造消息 ID，不依赖它保证关联。
- 平台接受不代表送达、人已读或同意；成员显式收悉另行记录。原业务提交与外部投递不是一个事务，不承诺端到端恰好一次。
- 机器人受控能力或默认链路隔离不满足时，只能开展通过安全检查的通知试点；不得启用共用身份或普通宿主问答作为替代。

## 7. 上线与重新测试

1. **身份和权限底座**：配置新版用户登录／机器人应用，补齐客户端 UI、协议和服务器认证；建立管理员及项目参与资格。确认两端同人、异人隔离和撤销，不以更换配置文字替代认证。
2. **隔离宿主验证**：固定发布来源，验证 dsh-im 依赖、单消费者、管理接口及工具隔离。客户端／服务端配套升级，旧协议不能绕过扫码；能力不匹配明确拒绝。
3. **通信验证**：先通知试点，再受控双向与限定查询；验证真实群类型、私聊身份、ACK、关联和失败恢复。模型测试另行授权，不因接入自动换模型或产生后台模型调用。
4. **未来测试重置**：先冻结收发／队列、撤销旧设备登录和映射，再按核对清单清空限定数据，开启新测试批次。保留批次失效边界；旧钉钉回复、按钮或迟到消息不能进入新项目，不自动恢复旧请求。

重置前再次确认停服、备份策略、绝对路径清单与所有客户端范围；本次不执行，也不复用历史清库授权。清理本套测试业务、角色、资料／接收附件／解析、协作会话／请求／客户端映射、测试通信及订阅；保留程序、部署配置、模型／机器人凭据、SSH 密钥及必要的旧批次失效标记。成员绑定按验收计划复核，不自动换人／授角色；个人原件、其他 DSH 会话及整个持久卷不删除。平台上旧消息不保证删除。

上线失败停用新链路，保留诊断，不自动回到仅凭 SSH 的旧业务身份；已清空数据不能靠回滚程序恢复。通信记录的最小保存、访问、保留与删除策略需在正式使用前明确。

## 8. 验收与上线停止条件

- 同人扫码／IM 提问映射一致；外组织、外部联系人、未开通、撤销和 SSH 不匹配均被拒绝，登录结果重放／串客户端失败。
- 12 小时到期阻断该设备；设备退出不误停 IM，全局撤销阻断两端；资格变化与查询／写入／发送竞态不导致新的越权提交。
- 项目列表及关联 ID 不能跨项目越权；本人角色过滤、管理操作和逐角色确认不能被参数或提示注入绕过。
- 角色换人／资格撤销后待生效方案暂停，必须人修订重收确认；旧拒绝与历史保留，已生效决定不自动回滚。
- 公共群回答不泄露个人信息；无群校验能力／校验失效停止受保护输出；成员、项目、渠道和公开／私聊上下文不混用。
- 机器人管理命令、卡片审批、文件及默认会话同步均不能绕过受控链路；原请求有唯一归属和可追溯回复。
- 崩溃覆盖保存前／保存后 ACK、发送前／发送后和部分发送；不伪报成功、不重复登记，不盲重发未知结果。
- 重置后迟到的旧消息和本地映射失效，秘密、程序、个人原件与其他会话不受影响。

身份转换、统一权限、宿主隔离、受控钉钉接收或可靠登记任一未通过，**停止双向上线**；不以飞书测试、安装成功或本文修订代替真实平台验收。
