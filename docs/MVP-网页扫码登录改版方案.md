# MVP：网页扫码登录最小改版方案

状态：**用户已最终确认“确认，按网页扫码最小改版方案开始实施”，进入非破坏性实现／验证阶段**。本文件汇总[两轮设计访谈](<设计讨论-网页扫码登录回归.md>)，作为本次改版的共同理解；不表示扫码代码、CI、真实手机／电脑链路或部署已经完成。已实现的电脑钉钉方案继续保持原状，B的原PC验收与后续业务暂停。

## 1. 唯一变化：网页登录替代PC端内登录

```text
安装配套客户端 → 填既有统一HTTPS地址
  → 点击“钉钉扫码登录” → 自动打开默认系统浏览器
  → 钉钉官方页面扫码、本人完成官方授权
  → 回到原电脑浏览器的可信协作入口
  → 原DSH自动取得实际授权者的身份并保存7天设备登录
  → 管理员建项目／安排角色 → 成员选项目 → 原有业务闭环
```

- 不要求安装／登录电脑钉钉，不进入工作台，不手输16位核对码，不点“我已扫码”。
- MVP直接使用官方托管授权页，不在DSH内嵌二维码，不自建收集钉钉账号／密码的页面。
- 自动打开失败时允许明确重开同一次未过期请求，不新建请求或自动连续弹窗。
- 官方页面可能提供其他官方授权选项；本应用按官方授权结果认证，不伪称从OAuth结果就能证明用户一定使用了扫码。验收路径明确使用手机扫码，保留官方授权确认，不另加本应用的第二次“确认身份”按钮。

## 2. 保留的MVP与身份边界

| 领域 | 不变规则 |
|---|---|
| 服务接入 | 仍用一个可信HTTPS地址；无个人SSH、私钥包、JSON导入、hosts修改或逐人IP授权 |
| 成员 | 当前指定组织中有效内部成员首次官方授权后自动登记；同一人复用稳定身份，不按昵称另建／合并人 |
| 管理员 | 固定陈锦鸿，按官方组织内员工身份核验；不是首登者，不开放动态管理员／成员管理 |
| 项目 | 全部有效成员可见全部项目共享内容；只有管理员创建项目、安排九个固定职责 |
| 业务决定 | 由当前职责成员本人作正式决定；空缺阻断，换人不继承前任确认，相关未生效方案按原规则暂停／重收确认 |
| 会话 | 私人对话不共享；同一人换入口不改变会话所属成员／项目，另一个人扫码不能接管前任会话 |
| 附件与恢复 | 保留既有附件授权／隔离与业务能力；重连仅恢复记录，不重发指令或未知结果的管理／职责操作 |
| 范围 | 不做成员管理、项目ACL、机器人、通知、IM、全面IAM或新的后台业务自动推进 |

身份以实际完成官方授权的人为准。例如陈大海扫描A电脑的登录页并授权，就登录为陈大海，不能凭“电脑属于A”改成陈锦鸿。DSH显示实际姓名及管理员标记；误扫后退出当前设备、由正确本人重扫，不转移上一人的角色或私人对话。组织外／非有效内部成员拒绝。

只扫描本人在可信电脑页面发起的登录，不能替他人发送的二维码／链接授权；应用不猜测“这次本来想用谁的手机”。

## 3. 网络：手机普通网络，电脑仍用原专网

- 统一服务地址保持`https://login.lafinger.us.ci`，发起电脑仍须可通过现有LAN／ZeroTier到达它。
- 手机使用普通Wi-Fi／移动网络参加钉钉官方扫码授权，无需ZeroTier；浏览器回调由原发起电脑访问。
- 不新增公网域名、认证中继、隧道、端口或业务入口，不开放整个DSH或shell。
- [官方网页登录文档](https://open.dingtalk.com/document/orgapp/tutorial-obtaining-user-personal-information.md)及其链接模式示例支持浏览器重定向的设计依据，但不代替实际A／B网络和手机测试。
- **若实机显示某个必需步骤仍要求手机访问专网，立即停下报告并重新讨论。** 不能把手机ZeroTier或临时公网开放作为未告知的“修复”。

## 4. 设备登录和一次请求的完整行为

### 4.1 设备资格

- 成功登录最长7天，固定到期，不随轮询、重启或使用滑动续期。
- 当前Windows A／B沿用系统CurrentUser安全加密存储；不把本服务token放入浏览器、可分享配置、SQLite、命令参数或日志，不用明文兜底。
- 每台设备独立登录；“退出当前设备”终止本机资格，不全局停用成员或退出其他设备。离线退出仍清本机密文；远端撤销未确认时明确报告，不伪报完成。
- 组织资格沿用最多5分钟有界复核；官方暂时不可用则暂停业务，不因此延长7天或伪装成功。
- [钉钉个人用户凭证](https://open.dingtalk.com/document/isvapp/obtain-user-token.md)的2小时／刷新期限不等于本服务7天期限；不额外长期保存官方refreshToken或采集无关手机号／邮箱。

### 4.2 一次登录请求

| 情况 | 预期行为 |
|---|---|
| 正常发起 | 同一台DSH只有一个当前请求，最多5分钟；明确点击后才打开浏览器 |
| 快速双击 | 不创建多个登录，不连续弹出浏览器 |
| 重新打开 | 只重开原未过期请求，不延长有效期 |
| 完成官方授权 | 校验组织／员工资格和当前请求，自动交付原DSH；页面可显示授权已处理，但不能把它当作原DSH已领到凭据的证明 |
| 主动取消 | 服务端原子判定取消；取消成功后迟到回调／领取不能恢复登录。若登录已先完成，显示真实已完成状态并可退出，不谎报取消了既有登录 |
| 超时／拒绝／错误组织 | 清楚提示并停止本轮轮询，由本人明确重新发起，不重试旧码或旧回调 |
| 关闭浏览器 | 不保证等同于取消；原请求到期失效，或在DSH明确取消 |
| 断网、结果未知 | 先查询／恢复原请求或既有登录状态，不自动新建请求、重复换码、重新授权或延长7天；无法继续则明确要求重扫 |

原DSH证明、浏览器与请求绑定、随机state、短时限、一次性授权码消费、禁止其他设备抢领及取消／领取并发保护属于必要认证正确性，不增加用户手工步骤。敏感查询串不落代理访问日志或错误正文，回调后转到无授权参数的结果页。

## 5. 切换：保留数据，仅让原PC设备重新扫码一次

这是对**当前新MVP**的认证改版，不是再次“全新开始”，也不是恢复已删除的旧SSH协作系统。

1. 保持既有组织／应用／服务标识和稳定成员账号，保留项目、职责、资料／业务记录、私人会话、项目归属、本地映射及不重发日志；不清库、不按姓名重建人。
2. 完成新扫码的隔离真实验证及固定成功CI后，才在无正在执行业务写入时进行正式切换；停机窗口只用于必要的部署／认证元数据变更。
3. 切换时一次性撤销仍有效的PC设备登录、作废旧PC待完成请求并关闭PC免登入口。A／B分别用扫码建立新设备登录，此后恢复正常7天记忆，不长期维护两套入口。
4. 客户端只按明确失效结果处理旧登录密文并提示重扫，不因发现版本改变就删除普通会话、项目映射或用户文件。过期／取消的请求不重放。
5. 失败停止新登录／业务并核对实际状态；不静默回退旧SSH身份、PC免登、绕过TLS或重复执行切换操作。

**实现时特别防止误用旧的“全设备重置”方法：** 当前[通用撤销代码](<../src/identity-store.mjs>)会轮换与会话共同使用的epoch；[会话检查](<../src/service.mjs>)依赖该值，直接调用可能让保留的会话无法继续。新改版必须把“撤销PC设备资格／旧请求”与“成员或会话资格重置”分开，不轮换会话共同epoch、不提升成员revision、不误暂停方案；测试需证明同人扫码后仍可恢复原项目会话，其他人仍不能读取。

当前[身份存储](<../src/mvp-identities.mjs>)还带有认证模式及全新部署防护。实现应做明确的就地、范围受控认证元数据升级，不通过换serviceId、建空库、取消防护或扩大清理范围来绕过。

无论切换成功与否，保留admin0、系统／ZeroTier、应用秘密、证书、CPA与模型配置、源码、普通DSH会话及个人原文件；不顺带恢复或重复删除历史退役对象。

## 6. 已批准的最小实现范围

- **服务端插件**：在现有HTTPS运行时内实现账户未预分配的网页OAuth请求／回调／自动领取／取消，沿用组织身份提供器与自动登记、7天设备资格、原业务和会话鉴权。只添加必要登录路由，不恢复旧SSH前置或旧预绑定账号类作为生产回退。
- **客户端插件**：替换PC唤起为受限的默认浏览器打开，面板显示实际身份、等待／取消／过期与本机退出；沿用安全存储、项目菜单、附件及不重发。浏览器只能打开本服务生成的本次可信登录地址，不暴露任意URL启动能力。
- **配置／部署**：只核对必要钉钉网页登录权限和可信回调配置，在既有私网HTTPS反代增加最少路径；不泄露密钥，不为此改CPA或开启另一套业务宿主。旧版插件与新认证不匹配时明确要求更新并完整重启，不回退个人配置。
- **文档**：更新安装／使用／故障与验收边界，旧PC方案保留为历史。正式设计记录分别见[服务端认证改版ADR](<adr/0004-browser-qr-login-preserves-mvp.md>)及客户端仓对应ADR；用户已最终批准，当前实现及门槛进度见[实现与升级说明](<MVP-WEB-QR.md>)。

## 7. 实施与验证顺序

1. **用户最终确认**本方案后，先做只读现况核对及双插件的非破坏性实现；此时不撤销现用PC登录、不清理业务，不代用户扫码。
2. 本地隔离测试覆盖真实DSH Host／浏览器通信边界、默认浏览器打开、登录状态机、身份及会话隔离。钉钉／系统替身的通过只算自动测试，不算真实手机／浏览器验收。
3. 按既有要求：修改提交并推送GitHub，验证**同一固定提交**的Windows／Ubuntu CI及原始打包产物；未成功不提供正式切换版本、不绕过检查。不同端提交分别留证。
4. 用已验CI版本验证最小真实扫码链路：实际电脑网络＋默认浏览器＋普通网络手机＋本人官方授权＋原DSH自动取得身份，隔离验证不清正式库、不发业务模型请求。只有真实链路和网络目标通过，才做第5步。
5. 只读核对当前成员／登录及业务元数据、准确保留范围，确认没有执行中的写入，再维护切换正式插件／必要认证配置并执行第5节的一次性PC登录撤销。提交GitHub在先，同步服务器在后；不为验证替换当前DSH GUI服务器或强杀Host。
6. A／B各自从官方插件管理器安装固定版本并完整退出／重开DSH，各自本人扫码一次，先验A再验B。助手不代点授权；截图不含授权码／token／URL片段。
7. 两位身份及记忆测试通过后，才继续原MVP的一个最小双人项目／角色／资料→分析→方案→逐角色确认→任务→成果→接收演练。正式决定仍由职责本人逐次发起，不自动发送或补发未知结果。

## 8. 完成门槛

| 验收 | 必须看到的证据 |
|---|---|
| 登录体验 | 实际点击自动打开默认浏览器，不要求电脑钉钉；手机普通网络扫码并官方确认，原DSH自动取得实际授权者身份，无核对码／“我已扫码”／应用额外确认 |
| 身份与管理 | A为固定管理员；B自动登记为普通有效内部成员，没有创建项目／改角色权；错组织、抢领、重放被拒 |
| 设备 | 7天固定期限，重启恢复身份且到期不变；独立设备不互退；本机退出及失效旧PC资格不能再用于业务 |
| 失败 | 打开失败、取消、迟到回调、过期、双击、断网未知结果不产生重复登录／隐式重发；错误提示不含秘密 |
| 保留 | 正式成员／业务数据不丢失，同一人扫码后原会话归属与恢复有效；换人无法读取旧人的私人对话，不因切换改变项目或决策历史 |
| 网络 | A／B电脑原LAN／ZeroTier路径＋手机普通Wi-Fi／移动网络真实通过，未增加公网入口或关闭TLS校验 |
| 最小业务 | 仅管理员建一个演练项目与分配两职责，B无需项目授权可见；小附件／分析／方案／职责本人确认／最小任务成果／独立接收跑通 |
| 发行部署 | 双端固定SHA、双平台CI、原始包校验、服务器同步与实际运行版本可核对；不以代码／CI／PC旧测试代替扫码和业务验收 |

7天极限、组织复核、重放及并发等使用可控时钟／合成数据回归，不声称已经现实等待7天。手机回调、官方权限或现用Host出现未预期限制时，先报告阻碍和最小替代，不扩大范围冒充完成。
