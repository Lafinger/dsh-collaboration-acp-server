# 0.7.2-rc.13：组织撤权不重发旁人任务通知

修复rc.11/rc.12组织资格冻结与机器人通知去重的交互缺陷：此前把项目中任一冻结职责追加到全项目职责指纹，导致其余健康成员既有任务的通知绑定也变化，后台扫描误判为新通知，并可能重新生成文件下载链接。组织资格变化不是职责安排，本版恢复原职责指纹公式（项目、单调安排修订及原职责槽），不把冻结标记混入全项目指纹；无需回填旧通知键或改动历史通知/分享令牌。

安全约束不放松：撤权递增本人修订并撤销旧设备，职责读写与投影直接检查冻结状态；方案绑定保留各同伴修订；同身份重新扫码不解除冻结；管理员明确确认同账号职责仍递增安排修订。原短号不能因重新登录或确认职责复活。新的业务对象/版本、真正换人或明确重新安排仍按原逻辑通知，不自动重发旁人旧任务。

新增真实SQLite/官方宿主/合成机器人回归：已接受任务通知后撤销同项目另一历史职责持有人，现有绑定/通知/下载令牌不变，即使链接已过期或适配器重连也不重发；重新登录不自动解除冻结。真实成果评审短号与方案同伴短号在撤权、重新登录、同账号重新分配后均不复活。

协议、数据结构不变，继续使用客户端0.6.3-rc.9，由用户自行安装。本说明是代码修复范围，不是生产部署成功证明。rc.12实际候选启动后的现场差异及受控处理须由独立运维记录说明，不宣称从未尝试发送、不删除或覆盖原通知与下载令牌。公开rc.11/rc.12资产与标签保留。
