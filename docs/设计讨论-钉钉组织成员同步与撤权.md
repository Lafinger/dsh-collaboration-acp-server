# 钉钉组织成员同步与撤权：设计讨论

## 请求与授权

用户报告：钉钉组织已删除陈大海，预期目前只有陈锦鸿、陈小二；工作台角色候选仍显示两条陈大海和陈锦鸿。截图不作为身份匹配或删除依据。用户要求修复后提交、发布、部署，客户端由用户自行部署；通过 /grill-with-docs 先完成设计访谈并最终确认。Q1～Q10及最终整体方案已获用户“全部确认，开始实施”批准，实施与发布部署按下述确认边界执行；未满足验证门槛前不修改生产。

## 已确认：第一轮

用户回复“都按建议来”，确认 Q1、Q2。

- Q1：以钉钉确认的本组织有效内部人员资格和稳定身份为权威，不以曾登录或姓名作为资格。组织删除成员后，旧设备登录不得继续赋予项目访问、角色分配或机器人决定资格。不硬编码指定姓名名单，不凭同名合并或删除账号。
- Q2：撤销资格而非删除历史。保留资料、成果、审批及历史身份归属；不改记他人，不转交私人对话。

领域语言已记录至 [GLOSSARY](<../GLOSSARY.md>)：组织有效成员、成员显示姓名、成员停用。

## 已确认：第二轮

用户回复“都按建议来”，确认 Q3～Q5。

- Q3：保留失效成员原角色安排并明确标示组织资格失效、待重新分配；禁止失效成员继续履职，不自动转给其他成员、不自动同意待决事项。
- Q4：官方明确失效与超时、限流、权限范围不足等暂时不可核验分开；后者不能误报离职，也不能冒充同步成功。超过有效核验期限后拒绝受保护操作，提交角色分配仍服务端校验。
- Q5：保留首次官方登录自动开通，只同步已开通协作成员的组织资格和姓名，不导入全组织未使用者。新成员仍需首次扫码；改名不改变账号与历史归属。

## 已确认：第三轮

用户回复“都按建议来”，确认 Q6～Q8。完整设计仍须在最后边界收敛后取得最终实施确认。

- Q6：启动后及后台每5分钟对已开通成员主动复核组织身份与姓名，不被现有15分钟租约跳过；显式“刷新项目和角色候选”请求权威复核，服务端并发合并/短时防抖并显示实际核验时间。提交角色分配前服务端再次权威核验目标，不仅依赖缓存候选。正常网络下目标是一次5分钟巡检周期加请求耗时/排队发现变更，不承诺零延迟；故障标记核验不可用，过期操作停止。本次先采用轮询，不额外引入通讯录事件订阅。
- Q7：仅当前核验有效者可被新分配；明确失效者不作可选候选，未知者不可新分配并明确提示，原角色及最近成功核验时间可追溯。真实同名者保留，使用最小非敏感区分标记，不展示官方原始身份标识。
- Q8：组织删除后重新加入，即便官方稳定身份仍相同，也不得复活旧设备登录、旧审批短号或已暂停方案；本人需重新官方登录。保留原账号历史，职责恢复需管理员明确确认；不同稳定身份不继承旧账号或私人会话。单纯改名不触发撤权或要求重分配。

## 已核实代码事实

1. [adminView](<../src/mvp-service.mjs#L52-L56>) 只查本地 enabled=1 并连接姓名缓存，未读取实时组织资格；[manage](<../src/mvp-service.mjs#L58-L85>) 分配角色时会刷新指定账号资格。
2. [invalidateOrganization](<../src/identity-store.mjs#L107-L112>) 撤销登录并增加 revision/清空核验期限，但不改变 enabled；候选仍可保留。
3. [enroll](<../src/mvp-identities.mjs#L28-L43>) 以组织、应用和 userId 找稳定账号，姓名只作标签。不能从两条同名推断两个账号应合并。
4. [refresh](<../src/login-service.mjs#L65-L75>) 到期才重新核验，不调用 enroll；[verifyMember](<../src/dingtalk-identity.mjs#L65-L69>) 默认不取显示姓名，因此普通刷新不会更新姓名缓存。
5. 客户端直接按 account 渲染成员选项、只显示 name，不按姓名去重；姓名与身份相互独立。客户端自身登录姓名快照也需单独评估刷新。
6. 当前默认组织租约实际为15分钟，并非旧文档中的5分钟；后台现有资格监测不等于定时向钉钉查询。不能宣称当前已经保证15分钟内自动撤权。

## 官方接口事实

- [根据unionid获取userid](<https://open.dingtalk.com/document/orgapp/query-a-user-by-the-union-id.md>)：contact_type=0 是内部员工，1 是外部联系人；60121 为未找到对应员工。
- [查询用户详情](<https://open.dingtalk.com/document/orgapp/query-user-details.md>)：active 是是否激活钉钉，不是在职标记；33012 为无效 userId。两接口均需成员信息读权限。
- 当前 provider 只将数字33012识别为显式资格撤销；60121进入普通不可用，且把 active=false 误当资格永久撤销。需要按具体接口和已确认身份分类，不能把任意权限/网络错误当离职。

## 已确认：第四轮与最终实施授权

用户通过确认工具选择“全部确认，开始实施”，接受Q9、Q10及Q1～Q8完整范围，并批准实施、测试、提交、发布和服务端保全部署；客户端由用户自行安装。

- Q9：本次撤销成员认证访问和职责决定资格，但不重做独立 bearer 下载服务。既有共享文件链接仍按原有效期可转发访问，不能按接收人的成员资格单独撤销；不批量作废影响其他成员的共享链接。已下载文件无法追回。若要求离职者不能继续使用旧链接，需要另行设计成员绑定下载和既有链接迁移，不可假称本修复已实现。
- Q10：确认组织资格失效后，终止对应设备/协作连接和在途轮次，禁止后续工具提交与职责决定，停止向其新增通知；已成功提交的事实和平台已接收的消息保留，不自动回滚/撤回，不自动换人重发。待决事项失效或暂停需明确显示，换人后走原业务重新确认流程。

## 实施范围与部署限制

Q1～Q10及最终实施已获确认。实现涉及双端（资格/角色显示和本人姓名更新），客户端固定发行由用户安装；服务端部署允许本轮已批准的组织核验状态/撤权变化，不能套用“所有身份行绝不变化”导致跳过同步，也不允许无关业务记录变化。新同步在确认组织失效后可能按批准范围更新成员状态、撤销登录、暂停受影响未激活方案、终止在途请求；这些变化须可区分于无关业务漂移，并保留私有备份和审计。
