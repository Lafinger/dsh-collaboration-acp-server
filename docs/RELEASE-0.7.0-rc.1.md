## 相对旧正式版的变化

### 1. 机器人本人文本决定

机器人私聊通知并接受**本人固定版本事项**的六个动作：同意／拒绝、完成／退回、接受／拒收；命令带 8 位短号，否定动作必须带原因。

- 共享原业务权威、成员／职责／版本检查和事务，不另建审批引擎，不通过模型代批。
- DSH 继续承担资料、分析、方案、任务执行及成果提交。下游接收仍由人在 DSH 显式开放，不因上游完成自动开放。
- 持久消息去重、重复决定只读回、相反决定不覆盖；发送 unknown 不自动重发，旧命令不自动 replay。
- 短号没有普通时间 TTL；方案／成果／任务／职责等固定上下文变化使旧号失效，不把短号本身当授权。
- 缺少或非法私有配置时默认关闭。受保护启用边界为 Linux owner-file；Windows 离线测试通过不等于支持 Windows 生产机器人启用。

实现范围及历史决策见[最小方案](<MVP-机器人文本通知与职责审批-最小升级方案.md>)和[业务权威 ADR](<adr/0005-text-private-decisions-share-business-authority.md>)。

### 2. 分析参数错误不再误报权限拒绝

原会话首次 analysis_submit 的 inferences 为对象数组，而声明要求字符串数组。同版本、合成资料及内存 SQLite 可复现：官方工具在业务调用前抛 INVALID_ARGS，却被访问包装器统一显示为 PROJECT_ACCESS_DENIED。

[最小修复](<../src/project-access.mjs>)仅对 analysis_submit，在原鉴权及引用检查之后、业务调用之前执行同一官方 schema 校验，返回固定安全 INVALID_ARGS，不回显私有参数。

不全局提前校验其他工具、不调整生产 access(identity(original)) 顺序；保留认证人署名注入、服务器 workspace 路径防护及本人 todo／notice roles 覆盖。

[核心回归](<../test/project-access.test.mjs>)与[生产组合回归](<../test/project-access-binding.test.mjs>)覆盖：零 dispatch／零业务写、显式纠正后一次提交、跨项目仍先拒、身份补齐与伪造署名覆盖、workspace 错误优先级、非空双人事项的本人筛选。

**不是所有权限拒绝都代表未写入。** 执行后的资格或输出校验仍可能拒绝返回，原保护不变；测试保留“提交后抛错”的事实，不能据错误码自动重放。原日志无逐阶段遥测，同形复现是明确充分触发条件，不据此断言历史上没有并存的其他异常。
