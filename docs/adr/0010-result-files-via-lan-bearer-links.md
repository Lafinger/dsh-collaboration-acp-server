# 成果附件通过内网 bearer 链接交付，不新增客户端下载通道

状态：已接受（2026-10-30）。

下游角色在钉钉收到成果通知时只能看到文本预览：`material_read` 只返回解析文本，PDF/XLSX/图片拿不到原始字节，`result_list` 的文件项只有路径/哈希/大小，客户端也没有下载工具。决定在服务端新增一个只绑定局域网与 ZeroTier 地址的 HTTP 下载入口：通知里带一条成果版本链接，打开后列出该版本的全部原始文件，30 天内有效。令牌是 32 字节随机值，不校验成员身份；下载页只显示文件名、大小和下载按钮，并记录下载次数与最后下载时间。通知同时给出局域网与 ZeroTier 两条地址，共用一个令牌。

被拒绝的替代方案：在 DSH 客户端加反向 RPC 与下载工具（要改协议、双端发版，且 `result_list` 的文件项还缺 material 版本引用）；让钉钉机器人直接发文件（当前发送端固定 `sampleText`，没有文件能力）；要求浏览器扫码登录后下载（钉钉内置浏览器通常没有会话，摩擦大于收益）。代价是链接是 bearer URL，转发即可下载，且本轮只覆盖通知对应的成果附件，不包含项目全部资料。
