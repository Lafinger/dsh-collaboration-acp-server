# 资格巡检不得因租约到点而中止运行中的轮次，复核期限默认十五分钟

状态：已接受并实现于 0.7.1-rc.3 与 0.7.1-rc.4。协议未变。

线上出现的 `Remote turn cancelled; committed data remains` 不是模型或业务故障，而是自伤：后台巡检每秒对每个活会话复核一次资格，任何一次复核抛错都直接 `abort()` 该会话正在进行的轮次；而钉钉有限复核期限只有五分钟，于是一个正常的长轮次到了第五分钟必然被自己掐断。

三处一起改：巡检改为**先复核再判定**，只认真正的吊销（会话 epoch 变化、成员版本变化、被停用、登录链路失效），仅"租约过期"不再中止；`collaboration/login/status` 与业务正式操作前在租约已过期时先续期，避免把"该续期"误当成"已吊销"；复核期限默认五分钟改为**十五分钟**，上限六十分钟，显式配置越界即配置错误而不是静默替换。

复核期限放宽不等于放宽身份校验：续期走的是原有钉钉有限复核，成员被移出项目、设备被吊销、成员版本推进仍然立即生效并立即中止。

代价是成员资格的最坏过期窗口从五分钟变成十五分钟，且长轮次在中止判定上多一次真实身份复核；收益是正常对话不再被后台自己打断，也不必靠人工重发消息恢复。若将来需要更短的窗口，应改进的是续期路径的及时性，而不是重新让巡检去掐轮次。

钉钉扫码（`mvp-qr`）与宿主配置走**同一条**取值与上下限 —— 这条曾漏改一次：先只修了宿主路径，部署后核验发现线上配置是 `mvp-qr`，租约仍是五分钟，于是补了第二个候选版本。两条路径的默认值与上下限现在由同一组断言覆盖，任何一侧单独改动都会让测试失败。
