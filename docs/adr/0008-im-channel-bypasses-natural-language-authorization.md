# 即时消息渠道不进入自然语言授权判定，沿用既有旁路

状态：已接受，记录既有边界；本期不改行为。

DSH 侧的自然语言授权只处理"这个成员在当前这条消息里授权了什么业务写操作"。非 DSH 渠道（企业机器人私聊）不参与这套判定：其消息不经由 DSH 会话的人类授权消息元数据，判定函数对它直接放行。

这不是给机器人开放全部写权限。机器人有自己的窄执行器，只承认三类本人决定动作并配固定版本短号，其余写入不通过它发生；IM 渠道也不提供附件反向传输。也就是说，渠道旁路解决的是"这套判定不适用于非 DSH 消息"，写权限仍由机器人适配器自身收窄。

本期只把这条边界写清楚，不试图把机器人消息也塞进同一套子句授权。若将来要统一，需要先让机器人消息携带与 DSH 同构的人类授权元数据（消息 id、原文摘要、项目范围、附件范围），那是协议工作，不是正则工作。

代价是两条渠道的授权语义不同源，读代码的人容易误以为 `humanAllowed` 对所有渠道都做同一件事；收益是不在未验证的协议上强行合并，避免把"机器人可代批"这类越权口子顺手打开。
