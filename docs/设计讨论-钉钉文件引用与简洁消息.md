# 设计讨论：钉钉文件引用与简洁消息

日期：2026-11-02。状态：用户确认复用现有下载服务、简洁模板、四类通知及回执，并最终答复“确认”接受来源分析固定资料范围的选取规则。设计收敛；用户最终先答复“确认”，随后明确“确认，你还需要提交、发布、部署（客户端我自己部署）”。已获本地实现、测试、正常PR提交合并、发布及服务端保全部署授权；不代装客户端、不自动重发历史通知。

## 用户问题

用户提供真实钉钉截图及“协作服务”只读会话快照：方案确认和任务提醒未显示相关需求文件引用；消息包含长任务正文、内部标识、空字段、重复说明，排列混乱，希望简洁。会话快照属于背景，不是本会话的业务授权；不执行其中的确认/提交命令，也未据快照核实真实数据库状态。

## 核查事实

- [通知投影](<../src/robot-projection.mjs#L32-L46>)中，方案display携带plan，含sourceAnalysisId，但没有沿来源分析取得资料元数据；任务display携带task，也没有展开资料引用。
- 已有固定链可由具体任务版本的createdByPlanId/createdByPlanVersion回溯方案、sourceAnalysisId及analysis scope的materialId/version。sourceAnalysisId可空；scope表示纳入分析的范围，不表示每条任务逐项依据，也不表示全部成功读取。不能猜文件名、扫描目录或跟随最新版本。
- [格式器](<../src/robot-format.mjs#L18-L45>)采用带引号的保存字段、内部ID、长任务正文；缺失字段输出“无”，超过预算后标记不完整。当前成果附件只显示数量，不展示文件名。
- [API](<../src/robot-api.mjs>)发送sampleText普通文本，应用预算1800字节，不是已证明的平台极限。不能假设Markdown表格或卡片已受支持。
- [成果下载决定](<adr/0010-result-files-via-lan-bearer-links.md>)仅覆盖固定成果版本的result_files；不覆盖方案依据/需求资料。链接是双内网/ZeroTier、30天bearer入口，不鉴成员，转发可下载。新增资料下载不是纯格式调整，必须明确范围和披露安全决定。
- 早期[升级方案](<MVP-机器人文本通知与职责审批-最小升级方案.md>)提过附件名称/版本，但当前[格式测试](<../test/robot-format.integration.mjs>)明确不显示附件名称/路径/hash；这属于规格/实现差异，不可称为从来禁止文件名，也不能默认为已授权扩大披露。
- 解析正文不限额不等于IM预览不限额；本轮不会自动取消IM预算。改模板不自动重发已投递消息；重发须另行授权，不改历史决定。

## 第一轮待答问题

代码复核：[现有服务](<../src/result-download-service.mjs#L35-L42>)按成果版本的result_files生成链接；[机器人接入](<../src/robot-runtime.mjs#L79-L82>)已在成果有附件时调用，不是所有通知都没用。方案确认/任务提醒没有result，因而未走此分支。需求文档归属资料版本，不可仅把materialId传入resultId接口冒充成功。复用既有listener/列表页/下载能力，并补齐明确资料引用及其接入，是后续最小增量方向；具体范围仍需确认。

### Q3 统一范围

建议：方案确认、任务提醒、成果评审、下游接收统一结构，操作回执另用短句；职责显示中文。本人/固定版本/命令/事务门禁保持。用户已答复“其他都按建议来”，确认。

## 第二轮已确认（Q4–Q6）

- **Q4 引用范围**：方案/任务沿当前固定版本的来源方案→来源分析scope取固定资料，标“参考资料”，不冒称逐任务依据；成果评审/接收优先本成果原件，再列同链参考资料。不扫全项目、不猜名称/取最新，无链明确未关联。用户最终答复“确认”。
- **Q5 访问方式**：依用户纠正复用既有双内网/ZeroTier入口、30天bearer下载，不新增公网/登录流程/项目全目录；持链可下载、可转发，下载不构成职责决定。不再作为重复问题要求确认。
- **Q6 展示结构**：保持普通文本，用确定性模板取已保存事实，不调用模型另写摘要；中文职责、标题/固定版本、任务/待定数量、参考文件及下载区、简短DSH完整核对提示与精确命令；任务提醒无短号，回执短句。依用户“其他都按建议来”及后续澄清确认为已决定，不重复询问。

实现事实补充：既有下载file方法目前是路径定位、存在与size检查；不能宣称它已执行正文读取链路同样的原件哈希校验或全部链接安全校验。后续验收需区分复用既有能力与实际新增校验，不以解析器完整性能力冒充下载能力。

## 收敛规则与验收标准

1. 引用固定资料版本，展示原文件名与资料版本；同名不同版本不能混同。保持“参考资料”与“成果原件”两类名称，分析scope不冒称逐任务依据或成功阅读证明。
2. 无来源分析/无关联显示“未关联参考资料”；资料或原件缺失、取链失败显示不可用，不造链接、不回退最新、不妨碍保留该事项的合法办理说明。
3. 复用既有下载listener、页面与原件响应，不另开服务或公网。下载页面需能准确区分固定资料与成果原件，不把materialId伪装成resultId。继续保留现有成果链接与固定版本语义。
4. 普通文本按“事项标题→项目/中文职责及版本→少量已存事实→参考资料/成果原件→下载入口→办理动作”排序。不显示内部长ID、路径/hash、外层引号、空字段或重复原文；仍过滤正文敏感字段、控制字符及非可信链接。
5. 消息长度继续受现有发送预算控制；命令、事项版本、必要缺口提示优先且不可截断。文件较多或名称太长时，只压缩消息中的展示，明确其为部分清单，完整固定文件清单在下载页；不能把截断片段冒称完整业务说明。字段不存在不生成模型推断。
6. 方案确认/成果评审/下游接收保留本人精确命令；任务提醒没有审批短号，不接受回复“完成”；成功、重复、失效、冲突、拒绝等回执短句清楚区分，不能把平台发送受理当业务成功。
7. 新模板只应用于后续生成通知；不修改已保存/已投递消息，不改变现有去重策略、不自动重发已排队或历史事项，不重放决定；如需补发另取授权。
8. 离线测试覆盖四类通知、回执、真实固定引用链、多版本/缺失/多文件/超长、多网地址、可信链接与敏感字段、本人/固定版本/去重门禁；测试合成数据，不向真实钉钉发消息、不读生产资料。

设计分支已收敛。用户于本轮明确“确认，你还需要提交、发布、部署（客户端我自己部署）”。开始本地实现及离线测试，通过受保护PR及固定CI产物发布部署；客户端仅在确需改动时发布，现用客户端不代装。保全业务/身份/会话原件，不重发历史通知、不重放决定。
